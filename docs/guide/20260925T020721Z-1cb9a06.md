## Swapchain contract check

#222 already includes the important construction/replacement edges; no
specification amendment emerged from this review:

- A zero-area target is ineligible before extent clamping. Surface capabilities,
  formats, usage and image-count bounds are checked without copying the old
  proof's permissive choices.
- The configured live-generation limit includes active, constructing and retired
  generations. A limit of one retires and disposes the old generation before
  fresh creation rather than deadlocking on an impossible second slot.
- Passing `oldSwapchain` irreversibly retires the old swapchain even if creation
  fails. Partial construction, cancellation and uncertain cleanup retain owned
  state; they do not manufacture completion or reuse a retired handle.
- Newer resize requests survive an in-flight build, close wins, and one target's
  retirement/backpressure must not stop other targets' progress.
- Native resize and extent evidence on both accepted profiles accompanies the
  code PR. The newly merged fixture provides that path; it is not already proof
  that the unimplemented swapchain works.
