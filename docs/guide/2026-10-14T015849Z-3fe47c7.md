## Findings

### [#447] GUIDE-1. Report 2D window frames that can never be recorded, instead of refusing them every frame

**Disposition:** repair. Whether to refuse at publication or report a permanent refusal is the implementer's choice.
**Verification:** verified by reading the pinned code paths. No probe was run.
**Principle:** V-4 (retry needs proven safety and a finite budget; failures are explicit). render-2d design D-28: only pressure skips and retries a frame.
**Evidence:** `publish2DSnapshot` checks the session's depth format, materials, releases and failed chunks ([Window.hs:356](https://github.com/coghex/hetoimasia/blob/3fe47c7e5fea1b0d4572f44366e55638280cd68d/packages/render-2d-vulkan/src/Hetoimasia/Render/TwoD/Vulkan/Window.hs#L356)), then answers `Right revision`. Two conditions it does not check make every later frame of that window fail:
- **No window depth.** `frameWindowDepth` is `Nothing` when the host did not enable `vulkanWindowDepth`, which is off by default ([Window.hs:586](https://github.com/coghex/hetoimasia/blob/3fe47c7e5fea1b0d4572f44366e55638280cd68d/packages/render-2d-vulkan/src/Hetoimasia/Render/TwoD/Vulkan/Window.hs#L586)). A depth-enabled world layer is then `NoDepthTarget` ([Frame.hs:736](https://github.com/coghex/hetoimasia/blob/3fe47c7e5fea1b0d4572f44366e55638280cd68d/packages/render-2d-vulkan/src/Hetoimasia/Render/TwoD/Vulkan/Frame.hs#L736)). #426's spec said "The host adapter (#424) enables `vulkanWindowDepth`". The merged code instead makes it a host obligation, stated only in the README.
- **Storage region too large.** The region-size checks run only at recording ([Vulkan.hs:429–430](https://github.com/coghex/hetoimasia/blob/3fe47c7e5fea1b0d4572f44366e55638280cd68d/packages/render-2d-vulkan/src/Hetoimasia/Render/TwoD/Vulkan.hs#L429)). The region holds the clip tables (#442, with no cap on entries), frame tables (#445), and the material records of every chunk not culled (#443/#444). The window is 64 KiB by default.
- The adapter turns the refusal into `RefusedIllegal`, and "the host retries every refused frame" ([Window.hs:85](https://github.com/coghex/hetoimasia/blob/3fe47c7e5fea1b0d4572f44366e55638280cd68d/packages/render-2d-vulkan/src/Hetoimasia/Render/TwoD/Vulkan/Window.hs#L85)). The same module rejects exactly this for failed chunks: refusing them "would be retried at the host's backoff for ever" ([Window.hs:602](https://github.com/coghex/hetoimasia/blob/3fe47c7e5fea1b0d4572f44366e55638280cd68d/packages/render-2d-vulkan/src/Hetoimasia/Render/TwoD/Vulkan/Window.hs#L602)).

**Consequence:** a host that forgets `vulkanWindowDepth`, or a world whose visible chunks' records grow past the window as the camera pans, keeps getting `Right` from publication while the window never shows a new frame. The application is told nothing actionable; it can only scan per-frame refusals.
**Action:**
- Refuse at publication what can be known there: window depth (expose whether the host gives windows depth through `Host`), and the clip and frame tables.
- For the culling-dependent part of the region, either give the publisher a permanent-refusal outcome it can observe, or record without the overflowing content, as failed chunks are handled.
- Cover both cases with stand-in examples in `Test/Render/TwoD/Vulkan/Windows.hs`.

### [#448] GUIDE-2. Decide whether a held window with no live target may block every release request

**Disposition:** owner decision. It may become an issue amendment of D-28.
**Verification:** verified. The behaviour is intended and tested (`testTargetlessWindowHolds`, [Scenes.hs:573](https://github.com/coghex/hetoimasia/blob/3fe47c7e5fea1b0d4572f44366e55638280cd68d/packages/gpu-vulkan/glfw/test/Test/GPU/Vulkan/GLFW/Scenes.hs#L573)). Its consequence is not addressed anywhere.
**Principle:** V-5 (bounded communication, responsive ownership) and V-3 (release completes under its owner).
**Evidence:**
- A release request's barrier names every window the host holds, "whether or not it has a target yet" ([Scenes.hs:61](https://github.com/coghex/hetoimasia/blob/3fe47c7e5fea1b0d4572f44366e55638280cd68d/packages/gpu-vulkan/glfw/controller/Hetoimasia/GPU/Vulkan/GLFW/Internal/Scenes.hs#L61), [Controller.hs:2491](https://github.com/coghex/hetoimasia/blob/3fe47c7e5fea1b0d4572f44366e55638280cd68d/packages/gpu-vulkan/glfw/controller/Hetoimasia/GPU/Vulkan/GLFW/Internal/Controller.hs#L2491)).
- The barrier is met only by a *live* target's watermark, or by the host dropping the window ([Scenes.hs:353](https://github.com/coghex/hetoimasia/blob/3fe47c7e5fea1b0d4572f44366e55638280cd68d/packages/gpu-vulkan/glfw/controller/Hetoimasia/GPU/Vulkan/GLFW/Internal/Scenes.hs#L353)).
- Release requests run in order, and they occupy the shared action queue, whose default capacity is 64 ([Controller.hs:2376](https://github.com/coghex/hetoimasia/blob/3fe47c7e5fea1b0d4572f44366e55638280cd68d/packages/gpu-vulkan/glfw/controller/Hetoimasia/GPU/Vulkan/GLFW/Internal/Controller.hs#L2376), `Actions.hs:218`).
- A window can stay open with no target, for example after `VulkanHandoverRolledBack`/`Unavailable`, or because it is deliberately not rendered.

**Consequence:** while such a window is open, no texture or chunk release completes, so GPU memory is never reclaimed. render-2d-vulkan makes one request per release. After 64 of them, every `submitVulkanAction` is refused `ActionQueueFull`, which starves unrelated owner-thread work.
**Options:**
1. Name only windows with a live target or a publication.
2. Give blocked requests a bound of their own, separate from ordinary actions.
3. Keep the behaviour and document that an untargeted window must be closed.

**Recommendation:** option 1, which is what the internal Haddock already (wrongly) describes; see GUIDE-6. A window attached later adopts its published scene, and the scene's references are held from that adoption.

### [#449] GUIDE-3. Check retained chunks' materials from their precomputed set, not by scanning every instance each frame

**Disposition:** repair.
**Verification:** verified on the code path. The cost figure is an estimate, not a measurement.
**Principle:** render-2d's accepted R2D-10 and D-1 (retained content must not cost a per-frame pass over it, which is what D-1 rejected in Synarchy's rebuild).
**Evidence:**
- `unissuedMaterial` walks `chunkInstances` of every chunk each layer lists, culled ones included ([Frame.hs:831–843](https://github.com/coghex/hetoimasia/blob/3fe47c7e5fea1b0d4572f44366e55638280cd68d/packages/render-2d-vulkan/src/Hetoimasia/Render/TwoD/Vulkan/Frame.hs#L831)).
- It is called on every frame ([Vulkan.hs:415](https://github.com/coghex/hetoimasia/blob/3fe47c7e5fea1b0d4572f44366e55638280cd68d/packages/render-2d-vulkan/src/Hetoimasia/Render/TwoD/Vulkan.hs#L415)) and on every publication (Window.hs:356). D-1 republishes every frame.
- `chunkMaterialSet` is already computed at build ([Chunk.hs:190](https://github.com/coghex/hetoimasia/blob/3fe47c7e5fea1b0d4572f44366e55638280cd68d/packages/render-2d/src/Hetoimasia/Render/TwoD/Chunk.hs#L190)).

This arose where #443 (chunks) and #444 (materials) met; they merged the same day.
**Consequence:** with a 512 × 512 tile map (262k retained instances), each frame allocates and checks hundreds of thousands of list cells twice, once on the owner thread and once on the publisher. That cost grows with the whole retained world, not with what changed.
**Action:** check each chunk's material set, and find the offending instance only on the failure path. Materials are never unregistered, so a chunk checked at publication need not be checked again each frame.

### [#450] GUIDE-4. Keep display-helper cleanup and evidence retention intact through a stage's expiry

**Disposition:** repair (tools).
**Verification:** (b) is verified by a bash probe. (a) is verified by reading the code; how often it happens was not measured.
**Principle:** V-10 (evidence), V-3, and #370 requirement 4: "the termination grace and evidence retention" stay the same.
**Evidence:**
- **(a) Expiry signals the cleanup itself.** During the grace period, #408 sends SIGTERM to every process created since the first signal ([run.py:1281](https://github.com/coghex/hetoimasia/blob/3fe47c7e5fea1b0d4572f44366e55638280cd68d/tools/validation/run.py#L1281); [validation.md:1572](https://github.com/coghex/hetoimasia/blob/3fe47c7e5fea1b0d4572f44366e55638280cd68d/docs/validation.md#L1572)). That includes the helpers' own cleanup children: `x11.sh`'s `mkdir`, `cp` of the server logs into `--retain` and `rm -rf` ([x11.sh:108](https://github.com/coghex/hetoimasia/blob/3fe47c7e5fea1b0d4572f44366e55638280cd68d/tools/display/x11.sh#L108)); `wayland.sh`'s `rm`; and `run.sh`'s trap. Each is caught with probability roughly its lifetime divided by the 50 ms poll. The example "lets a termination handler finish cleanup that starts a subprocess" ([Execution.hs:507](https://github.com/coghex/hetoimasia/blob/3fe47c7e5fea1b0d4572f44366e55638280cd68d/tools/test/Execution.hs#L507)) ignores its child's result, so it proves only that the handler is not signalled twice.
- **(b) A signal can cut the helpers' `stop()` short.** `stop()` runs as the EXIT trap, while TERM/INT/HUP are still trapped to `terminate`, which calls `exit` ([x11.sh:124–137](https://github.com/coghex/hetoimasia/blob/3fe47c7e5fea1b0d4572f44366e55638280cd68d/tools/display/x11.sh#L124), [wayland.sh:112–123](https://github.com/coghex/hetoimasia/blob/3fe47c7e5fea1b0d4572f44366e55638280cd68d/tools/display/wayland.sh#L112)). A probe of the same shape exited 143 and left its scratch directory behind when TERM arrived during `stop()`'s `wait`. This predates the batch (2026-09-20), but #408's expiry SIGTERM now makes it reachable whenever a command finishes near its deadline.

**Consequence:** a timed-out X11 Vulkan stage can lose the retained server and window-manager logs (the evidence the grace exists for), leave scratch directories behind, or leave generated fingerprints in the checkout. This happens nondeterministically.
**Action:**
- (a) During the grace, signal only what was present at expiry, plus anything first seen after a failed first observation. Let the freeze and kill deal with the rest. Make the fixture's cleanup child write the evidence itself.
- (b) Begin both helpers' `stop()` with `trap '' TERM INT HUP`.

### [#451] GUIDE-5. Bound the texture registry's released-handle set

**Disposition:** repair (low).
**Verification:** verified.
**Principle:** V-3 (state has an owner and a finite lifetime) and AGENTS' state documentation rule.
**Evidence:**
- `ledgerReleased` gains one entry per released texture ([Textures.hs:81](https://github.com/coghex/hetoimasia/blob/3fe47c7e5fea1b0d4572f44366e55638280cd68d/packages/render-2d-vulkan/src/Hetoimasia/Render/TwoD/Vulkan/Textures.hs#L81)). The table release removes only the mark (`:179`).
- The README row says both "until the table release" and "the flag is never cleared" ([README.md:860](https://github.com/coghex/hetoimasia/blob/3fe47c7e5fea1b0d4572f44366e55638280cd68d/packages/render-2d-vulkan/README.md#L860)).
- The chunk registry in the same PR series keeps the generation per index instead, which is bounded.

**Consequence:** an application that streams or hot-reloads textures grows memory without bound for the life of the process, and publication checks against an ever-growing set.
**Action:** keep the highest released generation per index, and treat `(i, g)` as released when `g ≤ released[i]` and it is not live. That still meets #424's amendment that a released handle stays refused after its index is reused.

### GUIDE-6. Correct eleven comments and Haddocks that disagree with their code

**Disposition:** documentation drift. One small code-side item is (k). Each item is a one- or two-line fix in the next PR that touches the file.
**Verification:** each item was read at the pin.
**Principle:** AGENTS: implementation docs describe current behaviour.
- (a) `Mapping.hs:59,79,195,204` and render-2d README:635 call the inverse "exact". It is Float-rounded, and the round-trip tests use a 1e-4 tolerance (#418).
- (b) `Uploads.hs:550–553,609–610`: `UploadCancelled` says "its target was not initialized by it". An upload started and left unfinished by the exit was partly written; `retireUploads` settles it `UploadCancelled`, and the test at native `Uploads.hs:535` asserts exactly that (#390).
- (c) `Controller.hs:~1998–2001`, `requestVulkanRelease`: says the barrier names only windows with a live target or a publication. The code names every held window (#435; see GUIDE-2).
- (d) `Recording/Construction.hs:302–313`: `selectDepthFormat`'s Haddock now sits above `imageFormatOf`, which therefore has two blocks, and `selectDepthFormat` has none (#440).
- (e) `Recording/Table.hs:822–826`: `tableViewSets`'s `-- ^` doc now trails `tableViewSwaps` (#396).
- (f) render-2d-vulkan `Textures.hs:14–15,205–206`: "planning ignores marks until R2D-9". Since #440 the marks decide cutout routing.
- (g) `Frame.hs:392–394` and render-2d-vulkan README:115: the `RecordsTooLarge` text leaves out the frame tables #445 added to the region.
- (h) model `TextureTable.hs:123`: "growth arrives in GRS-14". It has arrived.
- (i) `Internal/Recording/WindowDepth.hs:14–16`: claims the recorder takes depth only from its own generation. It is the controller's sourcing that ensures this; the recorder does not check it.
- (j) `GLFW/Internal/Rendering.hs:71`: the state table omits that `prepareRendering` also makes the recording.
- (k) `MaterialSources.hs:221` `engineNames`: lacks `clipBase`, `clipCentre`, `inverseLinear` and `frameBase`. A material push field with one of those names fails with a raw glslang error instead of the named refusal `Material.hs:40–44` promises.

## What moved

- **GPU services (#383–#396):**
  - Offscreen targets with completion-gated readback; recording from buffers with a per-batch ring.
  - Bounded staging uploads, whose regions are freed only on completion, discard or loss.
  - The bindless table, with batch-frozen versions, growth and swap. Slot reuse requires that no live version maps the slot, and holds are taken in the bind's own transaction.
  - SPIR-V interface checking in the splice; compiler discovery is unchanged.
  - #389 and #391 close the prior pacing and fence findings.
- **Assets (#403–#407):** pure PNG, BC7, mip and KTX2 codecs. Arithmetic is Integer-checked before narrowing. The BC7 reference vectors come independently from Pillow.
- **Depth (#409, #412):** a depth image per swapchain generation, released only after generation disposal and batch completion. The scene3d oracle proves occlusion, not draw order.
- **render-2d (#417–#445):**
  - Pure snapshot, mapping, ordering and oracle packages.
  - The recorder, per-window scenes with release barriers, cutout depth, retained chunks, shader clips (D-31's no-clip-in-chunks rule is a refusal), application materials, and GPU frame selection with an exact host-side phase (D-32).
  - Readback matches the oracle on macOS, Linux X11 and Wayland.
- **Tools (#397, #408, #410, #411):** suite identity binds execution policy; stage sessions are held open and reaped at expiry (GUIDE-4); Lua fault runners settle; the Wayland helper reaps its readiness client.
- **Issues:** #371 (approved, open) is still accurate and buildable. Its line references are stale (Vulkan caller now `Private.hs:816`, GLFW regression `Guard.hs:329–331`), and #408 does not overlap it. Its fixture must keep the escaped writer outside the stage session or clean it up. #446 is deferred by design.
