## Findings

### [#505] GUIDE-1. Release lifecycle callback gates on assertion failure before protected teardown

**Disposition:** repair. **Verification:** verified. **Principle:** V-10; package-owned failure-path tests must produce bounded, useful evidence.

**Evidence:** [Lifecycle/Settlement.hs:75–81][settlement] enters the new `badinit` callback gate and makes two assertions before its straight-line release. No exception cleanup releases that gate inside `withBoundary`. [Support.hs:141–160][support] places the 60-second `timeout` around the entire supervised boundary. On failure, protected owner teardown needs the Lua callback to return, so the outer timeout does not make that teardown complete.

The original example passed. In the run's isolated checkout, the probe changed only the `badTid` inspection's expected substring from `status=initializing` to `GUIDE-INTENTIONAL-MISMATCH`, and printed a marker before that assertion. The marker confirmed entry into `badinit`. The process did not finish through the 60-second example bound; its independent 75-second process alarm terminated it with SIGALRM (`-14`, 75.011 seconds). This is a deliberate assertion-failure test of the harness, not evidence that the unmodified lifecycle implementation currently violates the inspection assertion. Source was restored byte-for-byte and the checkout was clean.

**Consequence:** a regression in the very behavior the example guards can hang the suite until its external job deadline, hiding the ordinary Hspec failure. PR #491 fixed the original initialization race but added this second unprotected wait. The earlier `init` and later `shutdown` gates in the same example group merit the same narrow cleanup audit.

**Action:** arrange gate release on every exit **inside** the supervised body, before leaving its boundary; preserve the phase assertions and the independent second gate. Verify by deliberately failing an assertion while each gate is held and requiring a bounded test failure. Do not weaken production protected teardown or replace the concurrency gate with sleeps.

**Deduplication:** #486's original race repair is merged; #487/#488 address different failures. PR #504's first two reviews already cover its new `Accounting/Windows` gates and timeout swallowing, but do not repair this merged `Lifecycle/Settlement` example. The published cursor had no open findings. No duplicate tracker item was found for this exact merged path.

Reproduction artifacts are retained locally under `.git/guide-evidence/2026-10-20T150446Z-4e70eff/`: `lifecycle-gate-probe.patch`, `lifecycle-gate-probe.log`, `lifecycle-gate-probe-result.json`, `probe-build.log`, and the passing baseline log. ## Why two PRs used five review rounds

**Both a design/integration gap and a verification gap are supported by the evidence.** The library originally exposed tick progress, not the stronger completion needed before the sample publishes its final state. An ordinary scheduled task cannot safely become that proof: its own slot, admission, result ownership and cancellation become additional lifecycle obligations. D-47/#503 supplies the missing public accounting observation without consuming a task slot. That corrects a missing prerequisite; it does not require replacing the accepted independent-owner architecture.
