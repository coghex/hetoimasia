## Findings

### GUIDE-1. Amend #201's impossible cancellation/join promise

**Disposition:** issue amendment, before solving. **Verification:** verified.
**Principles:** V-3, V-4, V-7.

The final clarification in [#201's approved review](https://github.com/coghex/hetoimasia/issues/201#issuecomment-5751534499)
says cancellation must stop the writer, wait interruptibly, and must not wait
indefinitely for a permanently blocked borrowed handle. The same specification
forbids skipping the join. Arbitrary callback sinks need not be interruptible:
native calls and uninterruptible regions may delay cancellation indefinitely.
An interruptible wait that lets the owner escape does not establish a safe join.

[The worker contract](https://github.com/coghex/hetoimasia/blob/d40c387765cda303d271423138481e1fbb837e1b/docs/workers.md#L225-L244)
requires dependencies to remain live until workers **and cancellation helpers**
finish, absorbing further owner cancellation during that drain. Its
[explicit limitations](https://github.com/coghex/hetoimasia/blob/d40c387765cda303d271423138481e1fbb837e1b/docs/workers.md#L284-L293)
disclaim both wall-clock termination and interruption of arbitrary blocking IO.
[RR-6](../runtime_review_findings.md) also explicitly disclaims bounded shutdown
for a permanently blocked sink. This is a contradiction in the effective issue
spec, not a defect in the current synchronous logger.

**Proposed replacement:** on owner cancellation, request writer cancellation
through the existing owned mechanism, then perform a protected drain until the
writer and its cancellation helpers are terminal. Repeated owner cancellation
must not release borrowed sink dependencies early. Preserve the original outcome,
account for abandoned entries and skip final flush under the existing policy.
A cooperatively interruptible write should terminate promptly; an arbitrary
uncancellable sink may retain the lifetime indefinitely. Never detach it or
run a competing flush to force progress.

Test both cases with coordinated gates: interrupt a cancellable blocked write;
then hold an uncancellable sink, cancel the owner twice, prove the borrow remains
live, release the test gate, and observe the completed join. No permanently hung
test is needed. Keep the other accepted amendments: aggregate text bounds,
bounded control state, terminal writer failure, and the one shared flush barrier.

### GUIDE-2. Correct the proof's nonblocking-presentation comments

**Disposition:** documentation drift in source comments. **Verification:** verified.
**Principles:** V-3, V-7.

[Publication.hs:24](https://github.com/coghex/hetoimasia/blob/d40c387765cda303d271423138481e1fbb837e1b/tools/vulkan-proof/proof/Test/Vulkan/Proof/Publication.hs#L24),
its Haddock at line 126, and
[Run.hs:1384](https://github.com/coghex/hetoimasia/blob/d40c387765cda303d271423138481e1fbb837e1b/tools/vulkan-proof/proof/Test/Vulkan/Proof/Run.hs#L1384)
describe the masked native presentation call as nonblocking.
[Vulkan explicitly permits `vkQueuePresentKHR` to block](https://docs.vulkan.org/refpages/latest/refpages/source/vkQueuePresentKHR.html).

The implemented repair still protects the enqueue-to-ledger interval and keeps
its result classification; the 94 headless examples pass. The misleading claim
could nevertheless be copied into production FFI selection or cancellation
latency guarantees. Haskell masking and `safe`/`unsafe` imports are different
properties; a protected handoff does not make the driver call nonblocking.

**Action:** describe the mask as covering the native operation and publication,
acknowledge possible driver blocking, and distinguish the later explicit waits.
Preserve the protection and the proof's safe imports. #199/PR #209 corrected
different comments in the C header, so it does not cover this newly identified
drift. A small source-comment repair should use the normal code PR lane.

### GUIDE-5. Make #208's changed-input macOS qualification gate explicit

**Disposition:** issue clarification before qualification. **Verification:** verified ambiguity.
**Principles:** V-8, V-10, V-11.

[#208](https://github.com/coghex/hetoimasia/issues/208)'s last acceptance bullet
permits recording that local native proof was not approved. Its
[new review comment](https://github.com/coghex/hetoimasia/issues/208#issuecomment-5751809782)

approval-free work meanwhile; ask the owner if the qualification policy must
change. This adds no hosted macOS job and no automatic desktop run.
