## Findings

### [#303] GUIDE-1. Ask for the replacement surface that a retirement's generations step admits

**Disposition:** repair.
**Verification:** verified by code trace at the pin; not reproduced.
**Principle:** V-6 (finite recovery budgets); #229 requirements 4–5 (an episode
that exhaustion decides).
**Evidence:** `prepareTargetRetirement` runs a generations step when a poll is
due and discards its summary:
[`Rendering.hs:1040`](https://github.com/coghex/hetoimasia/blob/50ceccea19e147537f33192c4b9118a97fab1443/packages/gpu-vulkan/glfw/controller/Hetoimasia/GPU/Vulkan/GLFW/Internal/Rendering.hs#L1040).
Since #293 that step also releases lost surfaces and admits a recovery attempt,
marking the target `SurfaceReplacing` and returning it in
`summarySurfacesWanted`
([`Surface.hs:109-113`](https://github.com/coghex/hetoimasia/blob/50ceccea19e147537f33192c4b9118a97fab1443/packages/gpu-vulkan/native/src/Hetoimasia/GPU/Vulkan/Native/Internal/Generations/Surface.hs#L109-L113)).
The only consumer of that list is the owner's step
([`Controller.hs:767`](https://github.com/coghex/hetoimasia/blob/50ceccea19e147537f33192c4b9118a97fab1443/packages/gpu-vulkan/glfw/controller/Hetoimasia/GPU/Vulkan/GLFW/Internal/Controller.hs#L767)).
A `SurfaceReplacing` target is never asked about again (`waiting`, Surface.hs:123-127),
and `generationsDeadline` owes it no step. The discarding call came from
`c4a8538`, in #294.
**Consequence:** Suppose window A closes while window B's surface has been lost,
and the step run for A's retirement disposes of B's last generation. B's
attempt is then admitted, but the main thread is never asked for a surface. B
never recovers, never exhausts, and never becomes unavailable. If B is
required, the session neither fails nor renders it. Reaching this needs a
surface loss to coincide with another window's close, so it is rare, but
nothing ends it.
**Action:** Hand `summarySurfacesWanted` from that step to `askReplacements`, or
keep a durable "asked" flag that the owner's next step re-asks from. Add a
headless example that closes one target while another's lost surface becomes
releasable in the same step.

### [#304] GUIDE-2. Keep the diagnostic-order wait from making masked failure bookkeeping interruptible

**Disposition:** repair.
**Verification:** partially verified. The mechanism was confirmed by reading
the code together with GHC's documented masking semantics. Reachability needs
two coincidences, and no probe was run.
**Principle:** V-3 (mask discipline; the primary failure and cleanup evidence
are preserved) and the Haddock contract at
[`Presentation.hs:151`](https://github.com/coghex/hetoimasia/blob/50ceccea19e147537f33192c4b9118a97fab1443/packages/gpu-vulkan/native/src/Hetoimasia/GPU/Vulkan/Native/Internal/Frames/Presentation.hs#L151)
("delivered only after that record is made").
**Evidence:** `orderBehindDiagnostics` runs `retry` while a sink failure has
claimed first place but not yet published its reason
([`Roots.hs:1080`](https://github.com/coghex/hetoimasia/blob/50ceccea19e147537f33192c4b9118a97fab1443/packages/gpu-vulkan/native/src/Hetoimasia/GPU/Vulkan/Native/Roots.hs#L1080)).
Every owner failure passes through it: `failRootsSessionBecause`, and the
failing transitions of `stateRootsModel` (Roots.hs:1447-1455). A blocking
`atomically` is interruptible under `mask_`. That covers the masked failure
records in presentation (for example
[`Presentation.hs:252`](https://github.com/coghex/hetoimasia/blob/50ceccea19e147537f33192c4b9118a97fab1443/packages/gpu-vulkan/native/src/Hetoimasia/GPU/Vulkan/Native/Internal/Frames/Presentation.hs#L252)),
in submission, in progress, and in the device-loss latch. The same function
also claims the capture's order through `unsafeIOToSTM`, which an aborted
transaction does not undo. Introduced in #292.
**Consequence:** Take a cancellation aimed at the owner. If it lands in the
microseconds between the sink worker's claim and its publish, while the owner
is recording an uncertain present, the record is lost. The frame then stays
`StageSubmitted` with an idle pool fence, the session is not failed, and a
later close may wait on a semaphore the presentation already consumed.
**Action:** The publisher is masked and does not block, so the wait is short and
bounded. Wrapping these failure transactions in `uninterruptibleMask_` is within
V-3's "short CPU release" allowance. Alternatively, latch the claim as pending
without blocking.

### [#305] GUIDE-3. Give a construction's reservation back when its out-of-memory retry re-raises

**Disposition:** repair.
**Verification:** verified by code trace against the pre-#293 file; not reproduced.
**Principle:** V-3 and V-6 (finite, accurate accounting), and the `construct`
Haddock ("its reservation is given back").
**Evidence:** In
[`Construction.hs:262-264`](https://github.com/coghex/hetoimasia/blob/50ceccea19e147537f33192c4b9118a97fab1443/packages/gpu-vulkan/native/src/Hetoimasia/GPU/Vulkan/Native/Internal/Recording/Construction.hs#L262-L264),
the out-of-memory branch runs `abandoned` only when recovery returns `Left`.
`failingAgain` re-raises device loss, cancellation and classified non-memory
failures (`Reclamation.hs:241-243`), and `reclaimOnce` can raise too. Those
exits skip `abandoned`. Before #293, every raise ran it.
**Consequence:** The attempt's bytes and objects stay charged to the model
for the rest of the session. This shows up as a phantom allocation in usage
and teardown evidence. If the session keeps running (for example, a classified
non-memory failure on the retry), it also lowers capacity.
**Action:** Run `abandoned` on every exit of the out-of-memory branch, for
example with `onException`, and add one headless example with a retry that
raises.

### [#306] GUIDE-4. Coordinate `testStalledLiveResize` instead of pacing it with real-time sleeps

**Disposition:** repair.
**Verification:** verified.
**Principle:** V-10, and AGENTS.md ("No timing sleeps for concurrency
correctness"). It also contradicts the module header's own "None sleeps for
correctness".
**Evidence:**
[`Loop.hs:473-501`](https://github.com/coghex/hetoimasia/blob/50ceccea19e147537f33192c4b9118a97fab1443/packages/gpu-vulkan/glfw/test/Test/GPU/Vulkan/GLFW/Loop.hs#L473-L501)
runs on the real monotonic clock (`visibleRig`). It paces 40 extent changes
with `threadDelay 8000`, then asserts at least 10 presents and 3 rebuilds.
The suite is in `test.vulkan-headless`, which Linux CI runs. Added in #294.
**Consequence:** On a loaded runner the owner can make fewer presents in the
paced window, and the example fails without a defect. Earlier memory records
that Linux CI exposes timing windows that macOS hides.
**Action:** Drive the scripted clock and count owner rounds per published
extent, or wait for each round's evidence before offering the next extent.

### [#307] GUIDE-5. Release the sample's pipeline layout when its pipeline is refused

**Disposition:** repair.
**Verification:** verified by reading; not triggered.
**Principle:** V-3 and V-6. `docs/gpu_backend.md` presents the sample as the
consumer to copy.
**Evidence:**
[`Triangle.hs:103-107`](https://github.com/coghex/hetoimasia/blob/50ceccea19e147537f33192c4b9118a97fab1443/samples/triangle/renderer/src/Hetoimasia/Sample/Triangle.hs#L103-L107)
builds a layout and then a pipeline. When the pipeline is refused, the layout
is neither cached nor released. The next frame builds another one. Added in
#302.
**Consequence:** Each frame with a refused pipeline build leaks one layout
until the session ends. Refusals include transient ones such as
`RefusedDiagnosticPending` and backpressure. A recurring refusal therefore
consumes the session-wide object budget that frame storage and readbacks share.
**Action:** Cache the layout separately from the pipeline, or release it on
refusal.

- **What was reviewed:** all 20 PRs, statically at the pin. Six read-only

- **Foundation moves:** checked mechanically by comparing the removed and added

  GUIDE-1 and GUIDE-2 are the ones a probe would firm up.
- **Retained native evidence** in #294 and #302 was reused as recorded. The
  headline numbers were re-derived from the retained records.

Notes that were not raised as findings:

- **Exit-drain spin (low).** The exit drain can spin on a deposited
  replacement (`replacementDeadline` answers "now"). It needs a lost-surface
  target whose own retirement failed while another target still owes
  presentations. That target is normally ready, and is retired in the first
  pass.
- **Wayland loss cause.** The Wayland probe reports a protocol error that is
  followed by a hangup as `TransportClosed`.
- **Hidden-module tests.** The foundation hidden-module tests disagree about
  whether they exclude the `:internal` unit.
- **Runtime component identity.** `unsafeComponent "runtime"` is defined twice
  (`Runtime.hs:9`, `Application.hs:201`). This predates the delta.
- **Pool records.** The model and the native frames keep separate pool records;
  a cross-check test would catch another divergence like #291's.
- **Module growth.** Vulkan modules grew in this delta: `Controller.hs` went from
  1197 to 1964 lines, `Roots.hs` from 885 to 1495, and `GPU/Model/Internal/State.hs`
  is at 3193. The owner has already sequenced the State decomposition after the
  foundation arc.
