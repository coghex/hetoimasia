### [#366] GUIDE-1. Preserve partial frame synchronization across rollback failure

> **Disposition:** Existing issue #366 — filed on 2026-10-01 for the partial frame-slot and presentation-pool ownership and cleanup failure described below. It supersedes the earlier no-issue disposition after the current construction paths and failure contract were rechecked.


**Verification:** source trace and executed headless fault-injection probe.
**Principles:** V-3, V-4, V-6; backend partial-construction and terminal-cleanup contracts.

**Evidence:** [slot rollback](https://github.com/coghex/hetoimasia/blob/50ceccea19e147537f33192c4b9118a97fab1443/packages/gpu-vulkan/native/src/Hetoimasia/GPU/Vulkan/Native/Internal/Frames/Acquisition.hs#L268), [pool rollback](https://github.com/coghex/hetoimasia/blob/50ceccea19e147537f33192c4b9118a97fab1443/packages/gpu-vulkan/native/src/Hetoimasia/GPU/Vulkan/Native/Internal/Frames/Acquisition.hs#L320), and [native failure guard](https://github.com/coghex/hetoimasia/blob/50ceccea19e147537f33192c4b9118a97fab1443/packages/gpu-vulkan/native/src/Hetoimasia/GPU/Vulkan/Native/Roots.hs#L878). Creation of a semaphore and first fence succeeds; creation of the second fence raises; fence destruction during rollback raises. The chained cleanup skips the semaphore, replaces the original exception, and never records the partially constructed slot. The caller returns the model reservation, leaving the session running. The injected probe then successfully retires target and device despite the forgotten semaphore.

**Consequence:** real created children can disappear from ownership accounting and allow parent destruction after unverified cleanup. Device destruction requires prior release of destroyable children ([Vulkan valid usage](https://docs.vulkan.org/refpages/latest/refpages/source/vkDestroyDevice.html)).

**Action:** retain partial objects and required parents, preserve both failures and terminal admission policy, and test slot/pool construction and naming rollback. Closed #182 repaired the retired proof harness; it does not cover this production code. Issue #366 now owns the repair.

Local reproducibility: evidence directory `guide-evidence/2026-09-29T121614Z-50cecce/` under the Git common directory retains `frame-rollback-probe.patch`, `frame-rollback-probe-qualified.log` and `native-prefix-build.log`. The one probe passed because it asserts the defective trace; it is not a passing safety assertion. The patch was removed from the checkout after execution.

### [#308] GUIDE-2. Coordinate cancellation delivery before the worker test releases its target

**Disposition:** repair, medium priority. **Verification:** source schedule, historical failure and deterministic scheduling probe.
**Principle:** V-10 and the explicit-coordination test contract.

**Evidence:** [testBlockedCancellationDelivery](https://github.com/coghex/hetoimasia/blob/50ceccea19e147537f33192c4b9118a97fab1443/packages/foundation/test/Test/Foundation/Workers/Spec.hs#L782) observes only the owner blocking in STM, then releases the worker. [requestCancelEntry](https://github.com/coghex/hetoimasia/blob/50ceccea19e147537f33192c4b9118a97fab1443/packages/foundation/internal/Hetoimasia/Foundation/Worker/Requests.hs#L76) independently forks the delivery helper. If that helper has not run, the released worker legitimately publishes success; the helper later sees a terminal summary and skips delivery. The test nevertheless requires `CancelledKind` and `RunCancelled`. [PR #289](https://github.com/coghex/hetoimasia/pull/289) records this exact failure during its validation.

The review inserted a temporary STM barrier delaying the helper until the target's terminal summary existed. This imposes that valid ordering without sleeps: the selected example failed with expected `[CancelledKind]`, actual `[SucceededKind]`. `worker-delayed-helper.patch` and `.log` retain the perturbation and result; production source was restored immediately afterward.

**Consequence:** correct worker behavior intermittently fails a mandatory test, and the named blocked-delivery example need not establish that delivery actually blocked. This is a pre-existing test defect surfaced by the refactor's validation, not a production refactor regression.

**Action:** coordinate the helper's actual blocked delivery before releasing the worker, preserving lifetime and cancellation assertions. Do not merely accept both outcomes or rerun until green. No matching issue was found.
