## What the milestone now establishes

- **Independent trusted domains:** separate UI and gameplay VM owners, scoped per-owner exposure, no synchronous cross-owner Lua entry, and coherent completed views. UI can progress while a gameplay segment is held; the application still owns admission and authoritative state.
- **Explicit gameplay progression:** logical grants carry explicit duration; deterministic placement orders intentions and controls. A tick stages its effects, waits for its owner to account for the work, then atomically commits world, dispositions, snapshot and digest. Ordinary task faults are consumed separately because the library accounting wait intentionally does not consume ticket results.
- **Failure and lifetime:** failed gameplay quiesces peers, preserves the last good world, closes admission and publishes one bounded failure result. Stop settles gameplay and provider/lease obligations before retiring owners. An accepted task handed over after a halt gets its own stop; halt recording cannot race past an in-flight grant issuance.
- **Reproducible sample evidence:** versioned canonical bytes and SHA-256, a trace beginning at tick zero and extending only on successful commit, a separate final published-state digest, bounded accepted-input recording, and replay through the same admission surfaces. File output uses exclusive creation and cleanup of an unsuccessful write. Replay reports an early failure/stop as incomplete.
- **A comparison that can fail:** the qualification checks every tick digest under gates, varying spin work, heavier UI activity, grant gaps, real-clock UI and replay without UI input. Seed, tick assignment and place-order changes produce divergence; control omission is also checked. Pause and the tick-six failure have dedicated replay checks. See [qualification assertions][qualify] and [fixture construction][fixedlog].

This does **not** establish hostile-code containment, hard memory/deadline limits, preemption of non-yielding trusted Lua, cross-platform/version identity, network lockstep, arbitrary scheduling-policy equivalence, visual behavior or a performance target. The sample has a fixed scheduling configuration, not a universal determinism theorem. Neither feasibility verdict has changed; the full Lua epic remains incomplete.

## D-48 and D-23

D-48 fits the vision as an explicit attribution boundary, with a material limit. Tick T owns the segments/resumptions its grants caused and every ending begun by the end of its final accounting boundary. Those failures must be recorded before T can commit. [Owner acknowledgement][accounting] follows boundary work, retained-failure checks and covered endings, including escalation return. The sample then consumes the faults of ordinary tasks T resumed and checks failure again in the commit transaction. See [driver and commit][commit].

A genuinely independent failure begun **after** that cutoff has no prior tick assignment. If recorded before T's commit it stops T; if recorded afterward T remains last good and the session fails at T+1, with no further grant. The [accepted amendment](https://github.com/coghex/hetoimasia/issues/499#issuecomment-6302661508) explicitly chooses this. It preserves last-good-state and explicit failure authority; it does not make the timing of unassigned asynchronous failures deterministic. Such executions are deliberately excluded from trace-equality qualification, as the [sample contract][qualification-contract] states. A future consumer needing reproducible asynchronous failures must assign them logical input positions or obtain a new contract; it cannot infer that guarantee from this milestone.
