## What is actually integrated

1. **Swapchain lifecycle is part of the engine's owner loop.** The integration
   controller constructs `Generations`, passes folded target geometry into
   `stepGenerations`, incorporates its deadlines, and retires generations
   before releasing a target's surface. It is exercised by shared native
   fixtures using production host/controller paths. Pure `Presentation`
   decisions stay independent of GLFW and Vulkan effects.
2. **Replacement has an explicit safety boundary.** The active generation is
   retired in the model when replacement is admitted; the native handover is
   recorded immediately before the call using `oldSwapchain`. Cancellation
   before that call does not pretend Vulkan retired it. Holds can keep the old
   generation alive, generation capacity is finite, and unchanged-geometry
   recovery uses the existing bounded episode rather than retrying hot.
3. **Recording owns references, not completion claims.** Managed layouts,
   pipelines, frame storage and readback buffers have explicit lifetimes.
   A batch retains each captured resource before the native command. Exceptional
   consumers leave partial storage owned; successful invalidation precedes
   release of recorded holds. `submissionCarries` gives positive evidence that
   a particular submission consumed the exact batch, rather than inferring that
   from its disappearance. Logical release and physical destruction remain
   distinct.
4. **Diagnostics fit the same identities and lifetimes.** Names derive from
   existing identities, and labels bracket batch/pass regions. Label failure
   cannot seal a batch. Capture uses preallocated bounded C storage, a shared
   text budget and distinct reported/copied queue and command-buffer labels.
   The native ABI assertions cover element offsets and array stride.

## Maintainability assessment

The dependency direction remains clear: pure model, native backend, and GLFW
composition have distinct jobs. The native backend does not import GLFW, and
the ordinary GLFW package does not acquire a Vulkan dependency. Native
marshalling is separated into `Recording/Vulkan.hs`; the audited unsafe
recording calls are isolated in `Internal/Commands.hs`. No application-wide
environment or game dependency was introduced.

The pressure point is module size: `Recording.hs` is 1,817 lines and
`Generations.hs` is 1,122. Recording combines managed-resource construction,
recorder validation, batch bookkeeping, readback, and disposal. That is a
maintenance risk as the vocabulary expands, but size alone is not a verified
defect. Their state has named owners and the contracts explain the lifetimes.
Do not delay #225 for a broad abstraction exercise. Add its lifecycle work
beside these modules; extract cohesive internals when the integration reveals
a concrete boundary. Keep one authority for each obligation.

The tests have substantial failure-path value: cancellation is coordinated with
gates rather than sleeps; replacement failures preserve the irreversible
handover; unknown destruction retains parents; caught recording failures still
prevent sealing; discarded/reset work does not become readback completion;
stale/released handles are refused before native effects; labels balance on
normal, exceptional and cancelled exits. The review fixes are present in the
merged implementation, rather than only promised in discussions.
