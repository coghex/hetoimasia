## What moved

**Lua ownership — [#460 / PR #461](https://github.com/coghex/hetoimasia/pull/461).**
The continuation-scoped owner protects initialization, use and close, then
releases dependencies. Foundation's `composeCleanup` reuses its existing failure
representation rather than introducing a parallel ledger. Cancellation tests
coordinate delivery during initialization, execution, finalization and retained
release, including 1,500 queued cancellations. Ten concurrent owners demonstrate
independent state and failure outcomes. These are general owners; fixed UI and
gameplay domains are a later composition.

**Lua modules and values — [#462 / PR #463](https://github.com/coghex/hetoimasia/pull/463).**
Registration is application-owned; each owner receives explicit namespace grants.
Modules have private environments, declared entry points and owner-bound handles.
The boundary checks bounded values and capability liveness, contains allocating
operations in C protection, and retains fault context without invoking arbitrary
error-formatting metamethods. Failed loads release their registry reference;
absent optional entries avoid argument processing and script effects. GC work is
serviced in permitted execution phases, with stress coverage for allocation-free
scripts that repeatedly marshal values. Public-client tests reject constructor
and record-update bypasses and run a real consumer of the exposed API.

The effective specification's accepted amendments matter: asynchronous requests
and lifecycle bindings may be described but calls return `NotYetSupported`.
That is the delivered contract, not a missing implementation finding. Trusted
scripts may still hang or exhaust memory; bounded crossing values are not a hard
VM execution or heap limit.

**Bounded launchers — [#371 / PR #453](https://github.com/coghex/hetoimasia/pull/453).**
Both native-suite launchers now own the child/reaper, both output readers and
parent pipe handles across setup failure, expiry and interruption. Tests retain
an escaped writer while checking reader completion and handle closure, so EOF
cannot accidentally prove reclamation. The two implementations differ only in
module name and explanatory header; they remain package-local test fixtures.
