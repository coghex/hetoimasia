## Finding

### [#237] GUIDE-1. Recognize completed X server exits with statuses above 128

> **Disposition:** Owner-approved issue [#237](https://github.com/coghex/hetoimasia/issues/237) filed on 2026-09-21. Implementation and canonical readiness remain pending.

**Disposition:** repair, tracked in #237.
**Verification:** verified by two Hspec probes on each supported local Bash.
**Principles:** V-4 accurate failure evidence; V-10 failure-sensitive tests.
**Priority:** medium; startup refusal remains a failure, but its cause and latency are wrong.

**Evidence.** At the pinned revision,
[`tools/display/x11.sh:218`](https://github.com/coghex/hetoimasia/blob/25a37d22d550afca2946c76e0f0293f0c8968948/tools/display/x11.sh#L218)
loops while `wait "$server"` returns above 128. Repeating a wait on a child that
completed with 143 returns the saved 143 again under both Bash 3.2.57 and 5.3.9.
Consequently the observer never reaches `printf 'exited\\n'`.

Using the existing `Display` fixture, an Xvfb stub wrote a log line and ended
with either `exit 143` or `kill -TERM $$`. All four probe runs failed:
the helper returned status 1 after about 30 seconds, saying
“the X server's startup report was closed or invalid before it named a display:
startup failed”. The required diagnosis was “the X server exited before reporting
a display”. The two-example runs took 60.14 and 60.29 seconds respectively.

**Consequence.** A crashed or externally killed server loses its termination
diagnosis and consumes the entire startup bound. The repeated completed wait is
also a busy loop until cleanup stops the observer. If an inherited writer keeps
the report channel open, the same control flow leaves no observed event and
selects timeout; that variant is traced here, not newly executed.
No false successful display acquisition was observed.

**Existing coverage.** #234 is closed by merged #236; its final canonical comment
approves `6662dd7`, but the new examples exercise an omitted status class.
The first review had discussed status 143 in a different, cleanup-induced
inference; the final loop has a new failure mechanism. Current open issues,
all PRs and searches for “X11 startup”, “Xvfb signal” and “wait termination”
found no open repair for this case. #207 owns Wayland qualification, not this helper.

**Smallest action.** File the bounded repair below. Keep the existing ownership,
observation channels and regression guarantees; do not reopen the whole display
or graphics design. Implementation, tests and corrected comments/docs belong in
one code PR.

## Approved issue filed as #237

**Title:** Recognize signal and high-status X server exits during startup

Labels: `bug`, `ci`, `tests`

## Background

At `master@25a37d22d550afca2946c76e0f0293f0c8968948`, `tools/display/x11.sh:218–222` retries `wait "$server"` whenever its status exceeds 128. A completed child can also return such a status. Bash retains that result for repeated waits, so the observer loops instead of emitting `exited`.

Two Hspec probes using the existing display fixture—an Xvfb stub ending with `exit 143`, and one ending with `kill -TERM $$`—both waited 30 seconds and reported “startup report was closed or invalid” instead of the observed server exit. Both failed under Bash 3.2.57 and 5.3.9. This contradicts #234's independent termination contract and `docs/validation.md`'s display-worker description.

## Requirements

1. Recognize completed server termination regardless of exit status, including a status above 128 and signal death. Distinguish any interrupted observer wait from actual child completion without repeatedly waiting on a cached completed status.
2. Preserve #234's outcome precedence, independent report/termination observations, owned signal cleanup, startup bounds, refusal status, log-tail evidence and consent isolation. A valid report still wins; cleanup-induced termination must not become startup evidence.
3. Add coordinated Hspec regressions for explicit high-status exit and signal death, including an inherited report writer remaining open beyond the bound. Assert the exit diagnosis, absent wrapped-command execution, process cleanup and scratch removal; safely clean fixture-owned descendants even on assertion failure. Keep existing regressions.
4. Reconcile the helper comments and `docs/validation.md` with the implemented distinction in the same PR. Do not infer child liveness solely from whether a wait status exceeds 128.
