## 1. Startup fixture ownership

### PRR-1. [P2] Protect the inherited-writer fixture's cleanup across failed assertions

> **Captured note:** The held-open startup-report example introduced by this PR only ends its own FIFO writer after all assertions pass. Preserve the teardown obligation when an assertion or cancellation unwinds the example.

**Verification:** Confirmed by a fresh static trace of the current pinned fixture and reuse of the bounded #240 witness executed at the same full SHA. The witness used the actual `tools/x11-test/Main.hs` fixture source and verbatim example action, with only a scratch module/export change. A controlled immediate helper response launched the actual `handedOffServer` stub, preserved its holder PID outside the temporary scope and returned exit 2. The example's expected-exit-1 assertion raised `HUnitFailure`; after `withHelper` unwound, `stopped holder` was false. Its output was `holder_survived_failed_example=True`. The witness then ended its own child and reported `witness_child_cleaned=True`. That fixture and witness compiled warning-clean under GHC 9.14.1 with `-Wall -Werror`. The current fixture, helper and associated build/harness closure were independently verified unchanged before reusing this evidence.

The witness is reused, not rerun in this invocation. It establishes the assertion-failure ownership path, not a current production-helper diagnostic failure; it did not wait out startup deadlines or run the optional suite.

**Evidence:**

- `tools/x11-test/Main.hs:75` — the inherited-report example calls throwing refusal and cleanup assertions before the sequential `ended holder` call.
- `tools/x11-test/Main.hs:345` — `handedOffServer` forks a shell blocked indefinitely on a FIFO and records its PID; the production helper did not create or own this descendant.
- `tools/x11-test/Main.hs:519` — `refused` throws on an unexpected exit status, diagnostic or command execution, so an oracle failure can bypass the caller's only writer teardown.
- `tools/x11-test/Main.hs:596` — `withHelper` brackets a temporary directory without installing process cleanup around the example. Removing that directory does not stop its blocked reader.
- `tools/x11-test/Main.hs:123` — the later high-status sibling already uses `finally` to retain the same cleanup obligation on failure.
- The merged `tools/test/Display.hs` addition placed `refusedStartup`, holder assertions and `ended holder` in this same unprotected sequence; PR #240 subsequently moved it into the current optional suite.

**Handoff context:**

- **Current behavior:** A failing status/diagnosis assertion, subsequent failed assertion or cancellation after the holder is recorded can unwind the fixture while leaving its shell blocked on a FIFO whose temporary directory has been removed.
- **Expected behavior:** Fixture-created descendants remain owned until they are stopped on success, assertion failure and cancellation. Cleanup preserves the primary test failure and touches only fixture-owned processes.
- **Scope and constraints:** This concerns test apparatus, not the production X11 helper's descendant ownership or a reason to promote optional probes into routine validation. Preserve the outcome assertions, startup bounds and consent guarantees.
- **Verification target:** A focused Hspec fixture check should force a failed status or diagnosis assertion after its holder starts, preserve that failure, and prove the recorded holder is stopped before the fixture returns. Cover cancellation at the same ownership boundary and retain successful held-open-report coverage.
