## 1. Reliable cancellation evidence

### [#369] PRR-1. [P2] Lua cancellation tests can lose their runner result after the catch

> **Captured note:** Coordinate cancellation issuance and protect the test runner's result publication. Its `try` catches only `evalChunk`; a late injected `UserInterrupt` can kill the unmasked runner before it fills `raised`, producing a bounded-wait failure even when the VM restored its state correctly. The PR disclosed this intermittent failure but left the same harness at the current pin.

**Verification:** Current source tracing establishes the unprotected catch-to-publication gap and the sender/release race. A fresh, bounded GHC 9.14.1 witness coordinated a pending `throwTo` at that exact gap and reported:

```text
runner_ended=UserInterrupt; result_published=False
```

The witness uses a synchronous stand-in for the operation's already-caught failure, which is the branch the callback-failure example permits. Its barrier holds the runner between the catch and publication; it uses `threadStatus` plus `yield` to wait for the sender to be blocked delivering the exception, then releases the runner. This schedules a legal interleaving without sleeps or random repetitions. An outer `forkFinally` observes termination so the experiment leaves no thread blocked. It constructs no Lua VM and does not cancel a callback thread. It proves the Haskell test-harness gap, not a fresh failure of the unmodified Lua suite or a production VM defect.

**Evidence:**

- `packages/scripting-lua/test/Test/Lua/Faults.hs:302` — the “keeps a cancellation from leaving a callback's failure for the next call” runner is a raw `forkIO`; `try @SomeException (evalChunk ...)` ends before the unmasked `putMVar raised outcome`. At line 306 the example injects cancellation, and at line 307 it waits for the result the runner may never publish.
- `packages/scripting-lua/test/Test/Lua/Support.hs:139` — `cancelling` forks the `throwTo` sender and immediately runs `release`. Waiting for `sent` afterwards establishes that the sender returned, but does not establish that cancellation was queued before the released call returned or before its catcher ended.
- `packages/scripting-lua/test/Test/Lua/Faults.hs:268` — the stack-restoration example has the same unprotected result publication. The borrowed-dependency example at line 327 repeats it and accepts any result at line 332, so it can also complete without proving cancellation occurred if the runner finishes before the sender runs.
- `packages/scripting-lua/test/Test/Lua/Support.hs:159` — the package already protects another fork/catch/result handoff with masking. The fault examples do not inherit that protection.
- [PR #241's validation account](https://github.com/coghex/hetoimasia/pull/241) records an uncaught `UserInterrupt` followed by “a bounded test call never returned” in the callback-failure example, reproduced in its unchanged base checkout. That observation is consistent with this path; a later passing run cannot eliminate the race.

The complete scratch witness can be recreated as `CancellationHandoffWitness.hs` and run with the qualified `runghc`:

```haskell
{-# LANGUAGE ScopedTypeVariables #-}
import Control.Concurrent
import Control.Exception
import Control.Monad (void)
import GHC.Conc (BlockReason(..), ThreadStatus(..), threadStatus)
import System.Timeout (timeout)

main :: IO ()
main = do
  afterCatch <- newEmptyMVar
  releasePublication <- newEmptyMVar
  result <- newEmptyMVar
  ended <- newEmptyMVar
  sent <- newEmptyMVar
  runner <- forkFinally
    (do outcome <- try (throwIO (ErrorCall "callback failure")) :: IO (Either SomeException ())
        putMVar afterCatch ()
        uninterruptibleMask_ (takeMVar releasePublication)
        putMVar result outcome)
    (putMVar ended)
  takeMVar afterCatch
  sender <- forkIO (throwTo runner UserInterrupt >> putMVar sent ())
  let queued = do
        status <- threadStatus sender
        case status of
          ThreadBlocked BlockedOnException -> pure ()
          ThreadFinished -> error "sender ended before the controlled handoff"
          ThreadDied -> error "sender died"
          _ -> yield >> queued
  Just () <- timeout 2000000 queued
  putMVar releasePublication ()
  Just terminal <- timeout 2000000 (takeMVar ended)
  Just () <- timeout 2000000 (takeMVar sent)
  answer <- tryTakeMVar result
  case terminal of
    Left e | fromException e == Just UserInterrupt ->
      putStrLn ("runner_ended=UserInterrupt; result_published=" ++ show (maybe False (const True) answer))
    _ -> error ("unexpected terminal result " ++ show terminal)
```

**Handoff context:**

- **Current behavior:** At the legal late-delivery boundary the runner terminates and the result cell stays empty. The example therefore reports a test timeout rather than inspecting the post-call VM state. A sender that starts after a successful runner has finished can also return without proving a cancellation was delivered.
- **Expected behavior:** Each example explicitly establishes the intended cancellation ordering and observes it, and every runner completion or exception settles its result exactly once. Result publication must remain protected from the cancellation the example itself injects. Preserve checks of stack restoration, escape-record draining, and borrowed-dependency lifetime.
- **Scope and constraints:** Repair the owning `Test.Lua.Faults` / `Test.Lua.Support` harness. Preserve the production owner-directed cancellation contract, the VM's native-call mask and bookkeeping, and the exclusion of the unsupported `callback-cancellation` diagnostic. Do not turn a passing random recheck into validation or weaken the production behavior to accommodate the harness.
- **Verification target:** A controlled regression must exercise cancellation after the operation's exception has been caught but before result publication, observe a settled runner result without a bounded-wait failure, and continue to inspect a real VM's post-call state. Also establish cancellation before releasing the parked callback in the relevant examples, so their cancellation premise can fail. Run the owning `lua-host-tests --test-options='--match faults'` once as the focused check; no callback-thread hazard, optional nontermination probe, or desktop session is needed.
- **Deduplication:** Fresh open-issue inventory and all-state searches for `UserInterrupt` and `callback race Lua` found no matching issue; the Lua callback-cancellation search found #230's now-corrected wording and #295's distinct re-entry guard. The postclaim #241 ledger row had no report/history, and the existing #173 report holds the wording correction rather than this runner race.
- **Remaining uncertainty:** No fresh unmodified-suite failure rate was measured, and the witness does not identify every possible cause of historical intermittent failures. It establishes one concrete current failure path, consistent with the PR's disclosed symptom.
