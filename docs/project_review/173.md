## 1. Accurate contracts for later Lua slices

### [#230] PRR-1. Align Lua boundary comments with the supported cancellation and diagnostic contracts

> **Captured note:** P3 — Several comments still describe behavior removed or
> rejected during this PR's repairs: complete callback-thread cancellation
> containment, numeric conversion through `lua_tolstring`, and reporting opaque
> Lua values by native address. Reconcile those comments with the implemented
> boundary so later VM-owner and registration work does not restore an unsafe
> path or depend on a guarantee the package expressly excludes.

**Verification:** At the verification pin, the callback module's introduction
says every synchronous or asynchronous failure is caught, and says cancellation
delivered inside a callback is handled the same way. The function's own later
Haddock and the README instead state that cancellation targets the VM execution
owner: a direct cancellation reaching the foreign-export prologue or epilogue
can end the process. The retained diagnostic that demonstrates this rejected
path still has comments claiming the later throws have nowhere to land and
that every cancellation was contained. The suite explicitly excludes this mode.

The fault module's introduction also describes the old implementation: numbers
converted by `lua_tolstring`, and opaque values reported with their address.
The actual code checks for an existing string before using `lua_tolstring`,
reads numbers through non-allocating numeric accessors and formats them in
Haskell, and reports opaque values by type alone. Its tests deliberately assert
those differences. This is a contradiction in the maintained contract, not
evidence that the old allocation or address-disclosure defects remain in code.

**Evidence:**

- `packages/scripting-lua/bridge/Hetoimasia/Scripting/Lua/Internal/Callback.hs:9`
  introduces blanket exception containment. Lines 12–22 promise containment of
  asynchronous failures inside callbacks and describe a fixed-message Lua
  placeholder. The marker described at line 100 is light userdata, with no message.
- `packages/scripting-lua/bridge/Hetoimasia/Scripting/Lua/Internal/Callback.hs:150`
  documents the narrower owner-directed contract; lines 168–173 acknowledge
  the foreign-export window but end with the incomplete prohibition that “no
  registration surface may start.” That ending does not express the actual
  restriction on publishing callback thread identities or leaving work beyond
  callback return, and can be read as barring the planned LUA-3 surface itself.
- `packages/scripting-lua/README.md:233` states the accepted cancellation
  endpoint and the process-termination limitation. `MEMORY.md:94` records the
  owner's 2026-09-18 decision. The final PR review also explicitly accepts this
  supported/rejected-path distinction.
- `packages/scripting-lua/hazard/Main.hs:228` describes the callback-thread
  cancellation mode as containment evidence for the suite. Lines 258–262 say
  later throws have nowhere to land, and line 283 assumes containment. In
  contrast, `packages/scripting-lua/test/Test/Lua/Hazard.hs:20` describes it as
  an unsupported-path diagnostic excluded from the suite; the `spec` below
  runs the other three modes only.
- `packages/scripting-lua/bridge/Hetoimasia/Scripting/Lua/Internal/Fault.hs:6`
  says strings and numbers pass through `lua_tolstring`, and line 9 says opaque
  values carry their address. `renderFailure` at line 167 and `readNumber` at
  line 193 implement the repaired behavior instead. The nearby implementation
  explanation explicitly prohibits those old paths.
- `packages/scripting-lua/test/Test/Lua/Faults.hs:223` requires opaque boolean
  and table errors to contain only their type names. Line 236 requires numeric
  rendering to use Haskell's formatting, explaining why Lua conversion could
  allocate after the protected frame is gone.
- `packages/scripting-lua/hetoimasia-scripting-lua.cabal:13` also describes a
  cancellation reaching a callback as re-raised at the Haskell boundary,
  without distinguishing the action's caught failure from unsupported direct
  cancellation of the callback thread. Include this package-facing wording in
  the same consistency pass.
