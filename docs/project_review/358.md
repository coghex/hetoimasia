## 1. Action admission and shutdown

### [#364] PRR-1. [P2] Owner-thread actions remain open through pre-drain host quiescence

> **Captured note:** Close action admission and refuse queued, unstarted actions when the runtime quiesces the host before ordinary workers drain. The new action gate observes only the graphics owner's separate handoff admission, which remains open until the later protected dependency exit. The documented early refusal therefore does not happen.

**Verification:** Reproduced headlessly at the pinned commit with the existing scripted `Test.GPU.Vulkan.GLFW.StandIn`, the real Vulkan controller, real graphics owner, and real protected host. A zero-target surface-free host starts one action held on an explicit STM gate. A second action is queued. After the public `quiesceWindowHost` transaction commits—the same transaction the application runner uses before ordinary-worker drain—the owner's handoff is still open, reading the queued ticket gives no outcome, and a new action is accepted. The probe then opens its gate, awaits all accepted tickets, and exits successfully. It leaves no blocked process and performs no native driver or window experiment.

Fresh output:

```text
owner_admission_after_host_quiescence=True
queued_ticket_settled_after_host_quiescence=False
new_action_after_host_quiescence=accepted
```

The probe's critical sequence, inside the existing `runRig` callback after `RootsReady`:

```haskell
gate ← newTVarIO False
running ← newTVarIO False
let holding = VulkanAction $ \_ → do
      atomically (writeTVar running True)
      atomically (readTVar gate >>= check)
Right held ← atomically (submitVulkanAction controller holding)
atomically (readTVar running >>= check)
Right queued ← atomically
  (submitVulkanAction controller (VulkanAction (\_ → pure ())))
atomically (quiesceWindowHost (vulkanWindowHost host))
open ← atomically
  (targetEventsOpen (ownerHandoff (vulkanGraphicsOwner host)))
settled ← atomically (readVulkanAction queued)
late ← atomically
  (submitVulkanAction controller (VulkanAction (\_ → pure ())))
-- Record open, isJust settled, and admission of late.
atomically (writeTVar gate True)
_ ← atomically (awaitVulkanAction held)
_ ← atomically (awaitVulkanAction queued)
-- Await late too when accepted, then leave the host normally.
```

**Evidence:**

- `packages/gpu-vulkan/glfw/controller/Hetoimasia/GPU/Vulkan/GLFW/Internal/Controller.hs:893` — `actionGate` refuses a terminal session or a false `stateOwnerOpen` predicate; it does not inspect host quiescence.
- `packages/gpu-vulkan/glfw/controller/Hetoimasia/GPU/Vulkan/GLFW/Internal/Controller.hs:2181` — the composition installs only `targetEventsOpen (ownerHandoff graphics)` as that predicate.
- `packages/gpu-vulkan/glfw/controller/Hetoimasia/GPU/Vulkan/GLFW/Internal/Actions.hs:132` — a queued ticket gets its early refusal only when this gate refuses. While it remains open, `awaitActionTicket` retries. Admission and start use the same gate.
- `packages/glfw/runtime-glfw-core/Hetoimasia/Runtime/GLFW/Internal/Host/Lifetime.hs:229` and `packages/runtime/src/Hetoimasia/Runtime/Application.hs:262` — the application runner uses `quiesceWindowHost` inside the supervision scope. Quiescence runs first; ordinary supervision then drains; only afterward does the managed dependency lifetime unwind.
- `packages/glfw/runtime-glfw-core/Hetoimasia/Runtime/GLFW/Internal/Host/Construction.hs:175` — host quiescence closes command, demand, input and attachment admission, refreshes cells, and requests retirement. It never closes the separate owner handoff.
- `packages/glfw/runtime-glfw-core/Hetoimasia/Runtime/GLFW/Internal/Owner/Start.hs:61` — `newOwnerHandoff` allocates that separate handoff; it is not the host's attachment-admission cell.
- `packages/glfw/runtime-glfw-core/Hetoimasia/Runtime/GLFW/Internal/Host/Lifetime.hs:266`, `packages/glfw/runtime-glfw-core/Hetoimasia/Runtime/GLFW/Internal/Owner/Lifetime.hs:149` and `:237` — protected dependency exit eventually invokes `beginOwnerExit`, which closes owner publications. That is after ordinary workers have drained, so it cannot supply their promised early ticket refusal.
- `packages/gpu-vulkan/glfw/test/Test/GPU/Vulkan/GLFW/Actions.hs:288` — the passing exit example returns directly from the host body and has an unmanaged fork await refusal. With no ordinary worker held in the supervision drain, it reaches the later protected exit and misses this earlier interval.
- `docs/gpu_backend.md:2004` and `:2154` — the contract promises quiescence refuses queued actions before ordinary workers drain. The trusted [#336 amendment](https://github.com/coghex/hetoimasia/issues/336#issuecomment-5898006065) explicitly requires that order.

**Handoff context:**

- **Current behavior:** In the interval after runtime quiescence and before protected dependency exit, action admission remains open and queued actions remain eligible to start. An ordinary worker awaiting an unstarted action still needs graphics-owner progress to finish draining; the queued callback can execute after the boundary that promises to refuse it. If owner progress is blocked, its eventual `beginOwnerExit` refusal lies beyond the worker drain waiting for that refusal.
- **Expected behavior:** The same pre-drain shutdown boundary must atomically refuse new actions and make each queued, unstarted ticket observable as `ActionRefused ActionOwnerClosed`, without waiting for the owner. A running action keeps its borrowed resources until it finishes. The graphics owner must remain able to perform the protected retirement and destruction work that follows ordinary-worker drain.
- **Scope and constraints:** Correct the GRS-15 action gate and its integration with the actual runtime quiescence boundary. Preserve surface-free bootstrap, the default first-surface mode, bounded immediate admission, terminal-failure precedence, action/frame serialization, at-most-once execution, and D-33's owner lifetime. Do not stop or destroy the graphics owner merely to refuse new application work, and do not introduce a forced-release or timeout path.
- **Verification target:** In a composed runtime with an ordinary supervised worker awaiting a queued action, coordinate a held owner action or backend step, then begin application shutdown. Prove that the queued worker receives refusal before owner progress is released, no queued callback starts, and a new admission is refused. Then release the running step and prove protected retirement and teardown complete in order. Keep the existing direct-host exit test, but add the distinct pre-supervision-drain case.
- **Deduplication:** The post-claim #358 ledger row has no earlier report or review history. Open-and-closed searches for `VulkanAction`, `surface-free`, `action quiescence`, and `owner actions drain` found #336 and historical lifecycle issues, but no corrective issue for this gate. Existing project-review reports contain no action/quiescence finding. This is new; no repeat, fixed-later, or recurrence classification applies.
- **Remaining uncertainty:** The controlled witness directly proves incorrect admission and ticket standing after quiescence. The ordinary-worker-drain consequence is verified by the runtime's nested lifetime trace; the probe deliberately releases its gate and does not attempt an unbounded shutdown hang. No live GPU or platform-specific behavior is needed for the gate defect.
