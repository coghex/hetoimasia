## 1. Bounded child resource ownership

### [#371] PRR-1. Reclaim the Vulkan child launcher's abandoned output readers

> **Captured note:** P2 — PR #356 copies a bounded child launcher that returns after abandoning output held open outside the child's process group, while leaving its two reader threads and pipe handles alive. Reclaim those owned readers and handles before returning, preserving captured output and the expired verdict.

**Verification:** Confirmed against `32eb02e3bcb5c7d99dc09b6edc35c90c42509c56` with GHC 9.14.1 and the pinned `Test.GPU.Vulkan.Native.Child` module. An attempt-owned Python child forked a descendant, which entered a new session with `os.setsid()`, kept both inherited output pipes open and waited indefinitely. The direct child printed a success line and exited. The Haskell driver invoked `launchCommand 0.05`, forced GC after return, and compared `GHC.Conc.listThreads` / `threadStatus` against the pre-launch thread list. After the deadline and two five-second grace periods:

```text
(ChildExpired 5.0e-2 ExitSuccess,"partial success\n")
[(ThreadId 46,ThreadRunning),(ThreadId 43,ThreadBlocked BlockedOnMVar),(ThreadId 44,ThreadBlocked BlockedOnMVar)]
```

The two blocked threads are the output readers, which still own the read handles and accumulators. The driver's `finally` killed its separately tracked escaped fixture; that PID was subsequently verified gone. No GLFW session was acquired.

**Evidence:**

- `packages/gpu-vulkan/glfw/native-test/Test/GPU/Vulkan/Native/Child.hs:84` — creates both parent read handles.
- `packages/gpu-vulkan/glfw/native-test/Test/GPU/Vulkan/Native/Child.hs:98` — forks both readers and discards their thread identifiers; the finalizers only mark completion.
- `packages/gpu-vulkan/glfw/native-test/Test/GPU/Vulkan/Native/Child.hs:123` — discards the last bounded output-wait result, then returns once the direct child is reaped.
- `packages/gpu-vulkan/glfw/native-test/Test/GPU/Vulkan/Native/Child.hs:129` — remaining cleanup signals the original process group; it never ends readers or closes the parent pipes.
- `packages/gpu-vulkan/glfw/native-test/Test/GPU/Vulkan/Native/Child.hs:133` — each reader remains in its read loop until EOF and can keep accumulating bytes after the launch returns.
- `packages/gpu-vulkan/glfw/native-test/Test/GPU/Vulkan/Native/Private.hs:431` — private scenarios now consume this launcher; `Compositor.hs` also uses it for readiness/version commands.

The minimal Python fixture is:

```python
import os, signal, sys
child = os.fork()
if child == 0:
    os.setsid()
    with open(sys.argv[1], "w") as pid_file:
        pid_file.write(str(os.getpid()))
    while True:
        signal.pause()
else:
    print("partial success", flush=True)
```

The driver snapshots `listThreads`, calls `launchCommand 0.05 "/usr/bin/python3" ["escape.py", "escaped.pid"]`, reads the escaped PID, and uses a `finally`-protected block to print the result, call `performGC`, and inspect additional threads. Its finalizer sends `sigKILL` to that escaped PID. Inspection must happen before killing the escaped writer, since its exit supplies EOF and hides the leak.

**Handoff context:**

- **Current behavior:** Each abandoned-output launch can retain two blocked reader threads and their pipe handles indefinitely. A writer that resumes output can also grow an accumulator whose caller has already returned.
- **Expected behavior:** On deliberate output abandonment, no output reader or parent pipe handle owned by this launcher survives return. Keep the deadline, direct-child reaping, process-group termination, partial output and `ChildExpired` outcome. The launcher need not own processes that escaped its group.
- **Scope and constraints:** The newly added Vulkan private test module copies the GLFW launcher's defect. Coordinate the repair with `docs/project_review/278.md#PRR-1`, which describes the sibling `Test.GLFW.Native.Child`; dispose of both entries as one coherent correction rather than two duplicate issues. Keep fixtures component-owned or in the neutral test-support library, and keep the regression headless with separately owned escaped-process cleanup.
- **Verification target:** A deterministic owning regression holds stdout/stderr write ends open outside the direct child's group, verifies expiry and retained partial output, and establishes that both readers and parent read handles are reclaimed before return. Preserve ordinary output collection, process-group termination and expiry verdict behavior.
- **Deduplication:** The complete open-issue inventory and all-state child-reader, pipes/launcher and `launchCommand` searches found no dedicated issue. Closed #284 addresses orphan reaping, not reader cleanup. The claim-held #356 ledger row has no earlier report/history. The sibling #278 report is linked for coordinated disposition; it is not an earlier finding in this row and therefore is not a canonical `--repeat`.
- **Remaining uncertainty:** The leak was observed freshly on macOS. Linux executes the same reader path but was not freshly reproduced; ordinary-run frequency was not measured.
