## 1. Cancellation fixture ownership

### PRR-1. [P2] Release and join the uncancellable logging fixture when its example fails

> **Captured note:** The uncancellable-write example forks an adapter lifetime, then releases its writer's sole gate only after throwing assertions and cancellation operations. Keep that gate release and lifetime join owed when the example fails or is interrupted.

**Verification:** A fresh bounded, headless public-API witness compiled 27 units with GHC 9.14.1 against the pinned runtime and foundation sources. It reproduces the example's raw fork/catch/result handoff, borrowed uninterruptible write, gate and pending flush. A controlled `ErrorCall` at the first assertion boundary is caught by the example's caller, without releasing the gate. The adapter lifetime and writer remain blocked:

```text
caller_failed=True; writer_terminated=False; completed=0; outcome_published=False
runner=ThreadBlocked BlockedOnSTM; writer=ThreadBlocked BlockedOnMVar
witness_released_gate_and_joined=True
```

The last line comes from the witness's own exception-safe cleanup, which releases its gate and waits for the adapter lifetime to return. No thread was deliberately left blocked. This is a controlled reproduction of the fixture's ownership failure, not a failure of the unmodified suite or of production cancellation. The production adapter correctly retains the borrowed sink until its writer is finished.

**Evidence:**

- `packages/runtime/test/Test/Runtime/AsyncLog.hs:784` — `cancellableAdapter` starts a separate raw `forkIO` lifetime and returns its handle/result/thread; its caller receives no scoped cleanup obligation.
- `packages/runtime/test/Test/Runtime/AsyncLog.hs:831` — the borrowed write waits on the example's own gate under `uninterruptibleMask_`; cancellation cannot substitute for opening that gate.
- `packages/runtime/test/Test/Runtime/AsyncLog.hs:843` — the trace assertion can throw before any cancellation or gate release. The held-outcome assertion at line 851 and completion assertion at line 852 can also throw before the sole release.
- `packages/runtime/test/Test/Runtime/AsyncLog.hs:854` — `putMVar gate ()` and the following lifetime-result wait run only in the successful sequential path; no `finally` or enclosing resource scope covers earlier assertions.
- `packages/runtime/test/Test/Runtime/AsyncLog.hs:150` and `tools/test-support/src/Test/Support/Bounded.hs:22` — the example's outer bound interrupts the example thread, not its separately forked lifetime, and installs no gate release or join.
- The current cancellation fixture is byte-identical to PR #213's merged head, `92de9bc374a5e804ae3c3aec41ae10568ee81469`; subsequent extraction of pure record preparation does not protect this path.

**Handoff context:**

- **Current behavior:** An early assertion failure or interruption can return from the example while its separately forked adapter lifetime is waiting for a flush and its writer is still parked in the borrowed callback. The result cell is empty and the borrow has not ended. A ten-second outer bound limits the example, but does not discharge these child-thread obligations.
- **Expected behavior:** The fixture releases its deliberately uncancellable operation and settles/joins its lifetime on success, assertion failure and cancellation, before the example's resources are abandoned. Preserve the original test failure and all existing assertions about protected drain, cancellation and exactly-once accounting.
- **Scope and constraints:** Repair the owning runtime test fixture. Do not weaken the production protected-drain contract, add a shutdown deadline, detach the production writer, or promote optional nontermination probes into routine validation. Cleanup must touch only fixture-owned threads and cells.
- **Verification target:** Add a coordinated Hspec fixture regression that fails an assertion after the borrowed writer has entered but before its gate is opened, retains the original failure, and proves the writer completed and the lifetime settled. Cover example-thread cancellation at that same ownership boundary. Retain the healthy two-cancellation example and run the owning focused `runtime-tests --test-options='--match "Asynchronous logging adapter"'` check once.
- **Deduplication:** The claim-held #213 ledger row has no previous report, evidence or history. A fresh complete open-issue inventory and all-state searches for `asynchronous logging cleanup`, `uncancellable writer` and `logging test gate` found no issue specifically tracking this path; closed #201 specifies the healthy cancellation behavior. Reports [#236 PRR-1](236.md#prr-1-p2-protect-the-inherited-writer-fixtures-cleanup-across-failed-assertions) and [#240 PRR-1](240.md#prr-1-p2-clean-up-the-x11-fixtures-inherited-writer-when-an-assertion-fails) describe the analogous unprotected teardown of an X11 FIFO process, a different fixture and correction. [#241 PRR-1](241.md#prr-1-p2-lua-cancellation-tests-can-lose-their-runner-result-after-the-catch) concerns late result-publication cancellation in Lua examples, not this unopened gate.
- **Remaining uncertainty:** No failure rate of the unchanged suite, process-exit behavior or native platform result was measured. The witness injects a controlled early oracle failure; example-thread cancellation is supported by the same static absence of cleanup and was not separately injected. The failure-path finding does not claim that the normal example currently fails.

```haskell
{-# LANGUAGE ScopedTypeVariables #-}
module Main where
import Control.Concurrent (forkIO, myThreadId)
import Control.Concurrent.MVar
import Control.Concurrent.STM (atomically, check)
import Control.Exception
import Control.Monad (void)
import qualified Data.Map.Strict as Map
import Data.Time.Calendar (fromGregorian)
import Data.Time.Clock (UTCTime(..),secondsToDiffTime)
import GHC.Conc (threadStatus)
import Hetoimasia.Foundation.Log
import Hetoimasia.Runtime.AsyncLog
import System.Timeout (timeout)

bounded action = timeout 2000000 action >>= maybe (error "witness bound expired") pure
main :: IO ()
main = do
  entered <- newEmptyMVar
  gate <- newEmptyMVar
  completed <- newMVar (0::Int)
  writer <- newEmptyMVar
  handle <- newEmptyMVar
  outcome <- newEmptyMVar
  let sink = callbackSinkWith
        (\_ -> uninterruptibleMask_ $ do
           myThreadId >>= putMVar writer
           putMVar entered ()
           takeMVar gate
           modifyMVar_ completed (pure . (+1)))
        (pure ())
      entry = LogEntry { entryLevel=Info, entryComponent=unsafeComponent "test.async"
        , entryTime=UTCTime (fromGregorian 2026 9 20) (secondsToDiffTime 0)
        , entryThread="thread", entrySource=Nothing, entryMessage="uncancellable"
        , entryFields=Map.empty, entryBreadcrumbs=[] }
  runner <- forkIO $ do
    result <- try . withAsyncLogAdapter defaultAsyncLogConfig sink $ \adapter -> do
      putMVar handle adapter
      writeEntry (adapterSink adapter) entry
      void (flushAdapter adapter)
    putMVar outcome (result :: Either SomeException ())
  let cleanup = do
        void (tryPutMVar gate ())
        result <- bounded (readMVar outcome)
        case result of
          Left e -> error ("unexpected cleanup result " ++ show e)
          Right () -> pure ()
        adapter <- readMVar handle
        status <- adapterStatus adapter
        done <- readMVar completed
        if statusWriterTerminated status && done == 1
          then putStrLn "witness_released_gate_and_joined=True"
          else error "witness did not settle its writer"
  flip finally cleanup $ do
    bounded (takeMVar entered)
    adapter <- readMVar handle
    bounded (atomically $ adapterStatusSTM adapter >>= \status -> check (statusControlPending status == 1))
    -- This is the real example's first assertion boundary, before its only
    -- putMVar gate. A controlled oracle failure leaves that call unreachable.
    failed <- try (throwIO (ErrorCall "controlled early assertion failure")) :: IO (Either SomeException ())
    case failed of
      Left _ -> pure ()
      Right () -> error "controlled failure was not observed"
    status <- adapterStatus adapter
    runnerState <- threadStatus runner
    writerState <- readMVar writer >>= threadStatus
    done <- readMVar completed
    settled <- tryTakeMVar outcome
    putStrLn ("caller_failed=True; writer_terminated=" ++ show (statusWriterTerminated status)
      ++ "; completed=" ++ show done ++ "; outcome_published=" ++ show (maybe False (const True) settled))
    putStrLn ("runner=" ++ show runnerState ++ "; writer=" ++ show writerState)
```
