## 1. Exception evidence at the logging example boundary

### PRR-1. [P2] Preserve exception context when the uploader example rethrows

> **Captured note:** The published uploader catches `SomeException` with `try`, then uses plain `throwIO` on three propagation branches. This keeps exception type and payload but resets its context, silently discarding retained resource cleanup failures. Preserve the propagated exception's own context in both the guide and its mirrored body, and assert evidence as well as exception type.

**Verification:** Confirmed at `5b56b17d5eb1af5ec10a1a5a28510f096096c825` using GHC 9.14.1 and the real public `withResourceLabelled`/`cleanupFailures` APIs. A scratch Hspec executable imported the current six `Worker reporting boundary` tests and extracted the guide's helper body verbatim from its current test module; exact substring equality with `docs/logging.md` was asserted before compilation. The warning-clean `-Wall -Werror` build compiled 18 units. Six existing examples and five initial controls/witnesses passed (11 examples, 0 failures), followed by the remaining reporting-cancellation witness (1 example, 0 failures). Passing witness assertions deliberately expect the current loss; these are verification of the defect, not correction receipts.

| Controlled path | Primary at observation | Retained cleanup failures |
|---|---|---|
| Direct resource body throws `ErrorCall "work failed"`, its release throws `IOException "release failed"` | original `ErrorCall` | 1 |
| Same resource failure, caught and rethrown through `rethrowIO (ExceptionWithContext (someExceptionContext failure) failure)` | same `ErrorCall` | 1 |
| Same resource failure through uploader, Error sink throws `IOException "sink failed"` | same `ErrorCall`; sink attempted once | 0 |
| Direct resource body receives actual `killThread` while gated on an empty `MVar`, release throws | `ThreadKilled` | 1 |
| Same actual cancellation through uploader | `ThreadKilled`; no diagnostic attempted | 0 |
| Work fails first; Error callback owns the resource scope, receives actual gated cancellation, then its release throws | reporting `ThreadKilled`; sink attempted once | 0 |

The cancellation witnesses coordinate entry with `MVar`s, hold the blocking reference, use bounded waits, and join their owned threads in `finally`; no timing sleeps or native sessions are involved. The unchanged six tests confirm the original success, ordinary terminal failure, actual work cancellation, synchronous reporting failure, actual reporting cancellation, and failing success-diagnostic policy.

**Evidence:**

- `docs/logging.md:938` — the Error-report attempt is caught similarly; `:943` uses plain `throwIO reportingFailure` for cancellation and `:944` plain `throwIO failure` for the earlier work failure. All three propagation paths reset context.
- `packages/foundation/test/Test/Foundation/Logging/Worker.hs:63` — the same helper is mirrored verbatim; its losing rethrows are at `:69`, `:80`, and `:81`. Existing assertions inspect concrete exception type/payload and reporting count, without providing cleanup evidence for these branches to preserve.
- `docs/resources.md:78` — the current resource contract preserves the primary exception's type, value, and attached context. `:1511` explicitly documents why `try @SomeException` followed by plain `throwIO` loses evidence, and `:1524` shows the preserving alternative.
- `docs/logging.md:965` — the guide says work cancellation escapes unchanged; `:974` describes primary-preserving reporting. Copying its actual example into a resource-owning worker breaks the current evidence contract despite preserving the documented type and payload.

**Handoff context:**

- **Current behavior:** The original failure precedence and one-report limit work, but a propagated cancellation or primary work failure loses cleanup evidence accumulated before it reached this boundary. The resource scope itself retains that evidence, as the direct controls prove. The generic logger does not cause the loss.
- **Expected behavior:** Each exception this boundary chooses to propagate retains its own type, payload, and attached context, including inspectable cleanup failures. Work cancellation remains unreported; cancellation during reporting still wins over earlier work failure; synchronous report failure still propagates the earlier work failure; healthy reporting still ends an ordinary failing worker; failing success diagnostics still propagate. Do not merge an earlier work failure's evidence into a distinct reporting cancellation.
- **Scope and constraints:** Correct the published example and its foundation-owned mirror together, with focused Hspec cases. The original #9 specification expressly asked for plain `throwIO` of the caught `SomeException`; faithful implementation of that historical requirement does not satisfy the current resource evidence contract. This is a guide/test-example defect, with no production consumer found; no logger, runtime supervision, filtering, or worker lifecycle redesign is required. Update the guide's stale `test/Main.hs` reference when touching its test description.
- **Verification target:** Run the owning `foundation-tests` Worker group and add controls that carry real cleanup evidence through all three rethrow branches. Assert primary type/payload, evidence label/count or identity, cancellation precedence, and report count. Deliver real `killThread` at a coordinated interruptible point for the cancellation cases and clean up/join all fixture threads. Healthy reporting and success-path policy must stay unchanged. Headless checks suffice.
