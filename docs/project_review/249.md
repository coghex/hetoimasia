## 1. Native diagnostic proof cleanup

### [#376] PRR-1. Preserve both failures when the VK-6 proof's instance cleanup raises

> **Captured note:** P2 — The VK-6 proof session's manual instance scope uses `onException` for quiescing destruction. If its body fails and the destruction action also raises, the cleanup failure replaces the original failure. Preserve the original exception and retain the destruction failure beside it.

**Verification:** At `32eb02e3bcb5c7d99dc09b6edc35c90c42509c56`, the migrated proof fixture acquires its instance under `mask`, defines `quiesce` as the measured `destroyInstanceQuiesced` action, and runs the body with `restore` and handles failure with `onException quiesce`. The exceptional handler does not catch or attach the cleanup exception. A raised quiesce therefore escapes in place of the body's exception. The enclosing production diagnostic lifetime correctly preserves the exception it receives, but it receives only that replacement; it cannot recover the original failure. `runDiagnostics` likewise sees and reports only the replacement.

A fresh, headless GHC 9.14.1 base-only probe used the same `mask` / `restore` / `onException` orchestration with distinguishable typed `Primary` and `Cleanup` exceptions. The caught exception classified as:

```text
(Nothing,Just Cleanup)
```

This proves the language-level loss on the two-failure branch. The fixture-specific conclusion is a complete static trace; no Vulkan destruction failure was induced, and the probe does not establish native lifetime safety.

**Evidence:**

- `packages/gpu-vulkan/glfw/native-test/Test/Vulkan/Proof/Diagnostics.hs:439` — the instance scope acquires the instance, defines quiescing destruction, and uses the fallible `onException` handler at line 442 without preserving both exceptions.
- `packages/gpu-vulkan/glfw/native-test/Test/Vulkan/Proof/Diagnostics.hs:219` — the outer diagnostic capture catches the session outcome; lines 225–227 turn the escaping exception into the stopped-session reason.
- `packages/gpu-vulkan/native/src/Hetoimasia/GPU/Vulkan/Native/Diagnostics.hs:119` — quiescing destruction runs `destroyInstance` through `afterLastCallback`.
- `packages/gpu-vulkan/diagnostics/src/Hetoimasia/GPU/Vulkan/Diagnostics.hs:561` — the production lifetime captures the body's already-selected exception before finalization; it has no access to the exception discarded inside the fixture.
- `packages/gpu-vulkan/glfw/native-test/Test/Vulkan/Proof/DiagnosticsSpec.hs:34` — native assertions inspect the completed facts or stopped reason, with no injected body-failure plus quiescing-cleanup-failure example.
- `docs/resources.md:66` — the failure table requires the body failure to stay primary and every cleanup failure to be retained beside it; `AGENTS.md` explicitly prohibits a hand-written acquisition/release pair that drops one of two failures.

**Handoff context:**

- **Current behavior:** A failure inside the VK-6 session followed by a raised instance-quiescing action loses the original exception's type, value and context. The outer diagnostic verdict is attached to the cleanup exception instead.
- **Expected behavior:** Retain the original session failure as primary and preserve the cleanup failure as inspectable secondary evidence. A destruction that raises must still establish no quiescence. Successful destruction must run exactly once, after the children and explicit messenger, before capture release.
- **Scope and constraints:** Correct the VK-6 native proof fixture introduced by PR #249 and migrated into the Vulkan package's native suite. Preserve the successful proof and its recorded callback/counter evidence. This is separate from the production lifetime correction in #253/PR #254 and from production frame-slot/presentation-pool construction reports #290/#291. Keep any required fixture contract or acceptance updates with the correction.
- **Verification target:** Add a headless, package-owned failure injection around the fixture's actual instance scope, combining an identifiable body failure with an identifiable quiescing-destruction failure. Assert original type/value/context, retained cleanup evidence, no fabricated quiescence and once-only destruction. Include success and body-failure/cleanup-success controls. The base-only semantics probe alone is insufficient repair acceptance.
