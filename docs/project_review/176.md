## 1. Memory-proof evidence

### PRR-1. Make the macOS memory workload retain the native bytes it reports

> **Captured note:** P2 — The optimized memory workload grows Lua strings but
> allocates only one shared 8 MiB native buffer. Its counter nevertheless claims
> 16 MiB per iteration, and the verdict claims that the workload grows Lua,
> native allocations, and the RTS. Correct the workload and its accounting, or
> identify this portion of the evidence as missing and revise the retained claims.

**Verification:** A fresh, warning-clean build of the unchanged helper at the
verification commit, using qualified GHC 9.14.1, Cabal 3.18.1.0, and the
repository's `optimization: 2`, produced optimized Core with one top-level
8 MiB buffer and no native accumulator in the recursive loop. No confinement
or exhaustion experiment was necessary to establish this defect.

Reproduce from a clean detached worktree at the verification commit, with the
qualified toolchain and GLFW pkg-config environment configured as documented:

```bash
cabal build exe:macos-confinement-helper \
  --ghc-options='-ddump-simpl -dsuppress-all -ddump-to-file'
rg --files --hidden --no-ignore dist-newstyle | rg 'Main.*dump-simpl$'
```

The review used the canonical liveness `run` wrapper with launch label
`memory-core-build`. The command exited 0. On this arm64 Darwin host the dump was:


**Evidence:**

- `packages/scripting-lua/macos/helper/Main.hs:194` accepts a `natively`
  accumulator but never observes it. Lines 201–207 construct the same pure
  `ByteString.replicate` expression each time, force only its length, prepend it
  to the unused list, and increment the claimed held bytes by 16 MiB.
- `packages/scripting-lua/macos/lib/Hetoimasia/Scripting/Lua/Internal/MacOS/Confine.hs:364`
  implements `hmp_grow_step` as one retained 8 MiB Lua string per call. At the
  reported 256 MiB ceiling, the loop has made sixteen such calls: 128 MiB of
  Lua payload, plus at most the one shared 8 MiB block, before allocator and RTS
  overhead. This is not 256 MiB of retained workload payload.
- `packages/scripting-lua/macos/test/Test/MacOS/Limits.hs:79` checks that a
  `Ceiling` report exists and prints `lastHeld` as proof of held bytes. The
  capped example at line 103 checks SIGKILL and the absence of `Ceiling`; neither
  example detects elimination or sharing of the intended native allocations.
- `docs/macos_confinement_verdict.md:222` says the workload grows Lua, native
  allocations, and the RTS together. The matrix at line 30 and the accounting
  discussion therefore claim a workload that the qualified optimized build
  does not execute.

**Handoff context:**

- **Current behavior:** Lua allocations grow; the intended per-step native
  allocations do not. The helper's `Held`/`Ceiling` reports overstate workload
  payload and the acceptance checks trust those counters. Existing evidence can
  still demonstrate a process killed under a cap; this finding does not claim
  that jetsam itself failed or that the profile is supported.
- **Expected behavior:** Evidence claiming mixed allocation growth must use
  distinct, materialized allocations whose lifetime spans the measurement, and
  its byte accounting must match the workload actually retained under the
  qualified optimized build. Otherwise record that evidence as missing, as
  issue #148's inconclusive-verdict amendment permits.
- **Scope and constraints:** Keep this a private proof correction and update
  the accompanying verdict in the same delivery. Preserve the independent finite
  workload ceiling and external guard. Do not promote the inconclusive verdict,
  change the supported platform contract, or introduce production process APIs.
- **Verification target:** Add evidence that detects buffer sharing and dead
  retention, independently of the loop's own counter, at normal optimization.
  If rerunning the proof, distinguish Lua, retained native payload, and measured
  footprint; retain corrected bounded-control/capped results together with the
  code. Compiler inspection above can reproduce the present defect without
  running the optional confinement suite.
- **Deduplication:** The fresh claimed ledger row had no prior report or
  history. The open issue inventory and all-state searches for `macOS memory`
  and `native allocation` found no dedicated repair. #148 is the closed
  originating proof issue; #145 is the open epic. No existing project-review
  finding covers this defect, and it is not a repeat or recurrence.
- **Remaining uncertainty:** This review did not rerun OS confinement or
  measure a corrected workload. It establishes the current compiled workload
  and invalid accounting, not the result a corrected native-growth experiment
  will produce. The Linux proof uses a different C allocation path and is not
  implicated by this finding.
