> **Captured note:** Close the graphics owner's lifetime port, demand and scene snapshots, and observation publications at the actual application quiescence boundary, before ordinary workers drain. **Verification:** A fresh headless witness at the pinned commit used the existing `Test.GLFW.Owner.Fixture.Rig`, real graphics worker, protected host and application runner. ```text

Queued lifetime events remain available for the owner to account for; completion evidence remains publishable; the graphics worker survives for protected retirement and destruction.

Preserve backend neutrality, existing window-only constructors, bounded nonblocking quiescence, exact incarnation custody, and the separate surviving owner group. Admission closure is not permission to release resources or to join the graphics worker early.

Before releasing it or advancing the graphics owner, prove that scene, demand, observation and lifetime publications refuse at the correct boundary. Then release the worker and prove queued target ownership, target retirement, whole-owner destruction and join finish in order. Retain the existing post-lifetime refusal examples.

## 2. Failure settlement at owner exit

### [#365] PRR-2. [P2] Preserve owner failures when the final wake raises

> **Captured note:** Include the owner's final wake in outcome settlement. It currently executes after body and retirement outcomes were collected but before they are raised with retained evidence; a wake exception escapes instead and discards both.

**Verification:** A fresh three-example Hspec witness used the existing fake backend and the real seam, graphics worker, protected host and wake classifier at the pinned commit. Startup raised `Scripted "startup"`; whole-owner retirement raised `Scripted "retire owner"`; destruction returned valid evidence. No target was attached. The host body waited for `ownerRunEnded` and returned. The seam's final empty-event post was varied:

| Final wake | Startup occurrences | Retirement occurrences | Result |
|---|---:|---:|---|
| Healthy | 1 | 1 | Startup primary; retirement retained |
| `GLFW_PLATFORM_ERROR` (65544) | 1 | 1 | Expected degradation; same failures preserved |
| `GLFW_NOT_INITIALIZED` (65537) | 0 | 0 | Only `NativeFailure`; cleanup list empty |

The count includes the propagated primary and every exception returned by `cleanupFailures`. All three assertions passed; the failing case is a controlled demonstration of current loss, not a successful correction. All calls ran against the headless seam and teardown completed normally.

The varying setup is:

```haskell
seam ← newSeam defaultScript
  { scriptPostEmptyEvent = \reporter →
      mapM_ (\value → reportError reporter value "scripted wake") code
  }
script (fakeStart (rigFake rig))
  (\_ → throwIO (Scripted "startup"))
script (fakeRetireOwner (rigFake rig))
  (\_ → throwIO (Scripted "retire owner"))
-- ownedHostCaught seam ...; await ownerRunEnded; inspect primary and cleanupFailures.
```

**Evidence:**

- `packages/glfw/runtime-glfw-core/Hetoimasia/Runtime/GLFW/Internal/Owner/Worker.hs:80` — `runOwnerAction` catches the original run outcome and obtains the protected drain result.
- `packages/glfw/runtime-glfw-core/Hetoimasia/Runtime/GLFW/Internal/Owner/Worker.hs:97` — it records completion, calls `wakeGraphicsHost`, and only afterward calls `settleOwnerOutcome`. The wake has no handler that incorporates its failure into the collected outcomes.
- `packages/glfw/runtime-glfw-core/Hetoimasia/Runtime/GLFW/Internal/Owner/Wake.hs:27` and `packages/glfw/model/Hetoimasia/GLFW/Internal/Notify.hs:161` — the wake discharges the registered obligation and propagates unexpected wake exceptions.
- `packages/glfw/model/Hetoimasia/GLFW/Internal/Session.hs:1435` and `:1451` — the real classifier degrades only expected platform errors; an unclassified code raises `NativeFailure`. A native operation table that raises also propagates its exception.
- `packages/glfw/runtime-glfw-core/Hetoimasia/Runtime/GLFW/Internal/Owner/Drain.hs:184` — `settleOwnerOutcome` is the code that keeps a body failure primary and attaches protected drain failures. It is skipped entirely by the failing final wake.
- `packages/glfw/runtime-glfw-core/Hetoimasia/Runtime/GLFW/Internal/Owner/Exit.hs:124` — without a delivering sentinel, the exit reads the worker outcome from the joined report. That outcome now contains only the wake exception; the original run failure was kept only as notification in the latch, and the drain failures never reached settlement.
- `docs/resources.md:63` and `docs/glfw.md:4235` — the contracts require a body failure to stay primary with cleanup failures retained, and describe the worker outcome as the store for failures that ended the run and its protected drain.

**Handoff context:**

- **Current behavior:** An unexpected final wake error replaces the original owner failure and all collected protected retirement failures. The failure notification may still retain the first original error, but the ordinary unsupervised constructor reports neither it nor the distinct retirement failure. A delivering supervision sentinel can report the original error separately; it cannot restore distinct drain evidence that never reached the worker outcome.
- **Expected behavior:** Preserve the original body failure as primary, retain each distinct retirement failure, and retain the final wake failure as additional evidence. With no earlier failure, report the wake failure itself. Expected platform degradation keeps its existing behavior, and notification accounting must settle on every path.
- **Scope and constraints:** Correct final outcome assembly in the generic owner. Do not downgrade programming/lifetime violations, retry the wake or backend disposal, fabricate evidence, or weaken protected destruction and join. Preserve exactly-once supervised reporting.
- **Verification target:** Add composed Hspec cases with and without `superviseGraphicsOwner`, combining body failure, distinct retirement failure, successful destruction and an unexpected final wake error. Count each original failure exactly once across the primary and cleanup context; keep healthy and expected-platform controls. Also cover a normal body with only drain/wake failures.
- **Deduplication:** The post-claim #238 history is empty. Complete open inventory and all-state searches for `owner wake failure`, `wake primary` and `wake drain` found the original wake and protected-lifetime issues, but no corrective issue for this final-wake settlement gap. Existing project-review reports contain no matching finding. This is new; no repeat, fix-link or recurrence classification applies.
- **Remaining uncertainty:** The real classifier and composition were exercised with scripted native error evidence. No machine's real GLFW wake was forced to produce `GLFW_NOT_INITIALIZED`, and no claim is made about its frequency. The loss after any exception from that call is deterministic.
