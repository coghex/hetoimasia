## 1. Failure transitions

### [#193] PRR-1. Settle safe observing-task failures after the session has failed

> **Captured note:** P2 — PR #179 admits and runs observing tasks after an
> unsafe session failure, but refuses every subsequent `reportFailure`,
> including a handled safe failure of that newly admitted task. Preserve the
> original session failure while allowing the observing task to settle once.

**Verification:** At the verification commit, a focused Hspec example first
reported an unsafe authoritative failure, then admitted, activated, and started
an `Observing` task. Reporting that task's `RecoverySafe` script failure returned
`Left SessionAlreadyFailed`. The returned session still held the task as
`Running`; `observeResult` returned `Left (NoTerminalResult ...)`. The expected
successful settlement assertion failed. The complete reproduction is below.

**Evidence:**

- `packages/scripting-lua/model/Hetoimasia/Scripting/Lua/Internal/Protocol/Session.hs:429`
  explicitly permits a failed session's observing tasks to run, ask providers,
  and watch endpoints.
- `packages/scripting-lua/model/Hetoimasia/Scripting/Lua/Internal/Protocol/Session.hs:1222`
  applies `notFailed` before examining the reported task or recovery safety.
  Thus the task's failure transition and `retire` at line 1252 are unreachable.
- `packages/scripting-lua/model/Hetoimasia/Scripting/Lua/Internal/Protocol/Session.hs:443`
  rejects any session retaining an unsafe failure. Its comment explains the
  intended protection against overwriting the original session failure, but
  the gate also suppresses independent handled task outcomes.
- `packages/scripting-lua/test/Test/Lua/Protocol/Failure.hs:128` proves observing
  work can start after failure and then ends without testing its failure path.
- `packages/scripting-lua/README.md:516` documents observing admission remaining
  open. `docs/lua_runtime_design.md:579` distinguishes handled task failures
  from unsafe authoritative session failure and forbids implicit restart.

**Handoff context:**

- **Current behavior:** The ordinary failure-reporting operation cannot retire
  a failing observing task after the session fails. Its active task and reserved
  terminal-result capacity remain held until another operation, such as explicit
  cancellation or stop, disposes of them. Repeating this path can exhaust the
  finite task capacity without producing the promised attributable failed result.
- **Expected behavior:** A safe failure of an admitted active observing task
  produces one failed terminal result and retires its live holdings normally.
  Preserve the original unsafe session failure and last-good-snapshot evidence,
  keep mutation admission closed, and preserve the prohibition on implicit
  restart, epoch advancement, or overwriting the terminal session failure.
- **Scope and constraints:** Repair the pure model delivered by #149 and align
  its failure tests and contract. This requires no VM, worker, scheduler,
  provider implementation, or change to D-7's authority policy.
- **Verification target:** Exercise unsafe session failure followed by admission,
  activation, running, and safe failure of observing work; assert the one
  observable failed result, released active capacity, appropriate owned-record
  invalidation, and unchanged original session failure. Retain rejection of
  stale, queued, retired, and duplicate task reports and unsafe restart paths.
- **Deduplication:** The open issue inventory and all-state searches for
  `"observing" "failure"` found no dedicated repair. #149 is the closed
  originating issue; #145 is the open Lua umbrella, not a repair of this path.
  The claimed ledger row had no prior report or finding links.
- **Remaining uncertainty:** None about the demonstrated transition failure.
  Its eventual production adapter has not been implemented, so no deployed
  interpreter hang is claimed.

## 2. Bounded failure evidence

### [#194] PRR-2. Enforce bounded copied storage for failure details

> **Captured note:** P2 — PR #179 promises a bounded, copied `FailureReason`,
> but `Text.take` retains the original backing allocation and the exported
> `reasonDetail` record selector permits callers to bypass the bound. Make the
> retained evidence bound hold through every supported construction path.

**Verification:** At the verification commit, constructing a reason from
1,000,000 ASCII characters produced a detail of logical length 512 whose backing
byte array still held 1,000,000 bytes. A separate client expression using only
the exported reason API compiled successfully:
`(failureReason ScriptFault "small") {reasonDetail = Text.replicate 1000000 "x"}`.
Its resulting detail length was 1,000,000. Two focused Hspec assertions failed,
one for retained storage and one for the bypass; the reproduction is below.

**Evidence:**

- `packages/scripting-lua/model/Hetoimasia/Scripting/Lua/Internal/Protocol/Failure.hs:16`
  says script-originated detail is untrusted and bounding it here keeps an exit
  record's size a function of its task count.
- `packages/scripting-lua/model/Hetoimasia/Scripting/Lua/Internal/Protocol/Failure.hs:61`
  describes a bounded, copied description and claims the hidden constructor
  prevents bypass. The actual `reasonDetail` field is exported at line 28 and
  declared at line 67, so record update remains available.
- `packages/scripting-lua/model/Hetoimasia/Scripting/Lua/Internal/Protocol/Failure.hs:80`
  stores `Text.take reasonDetailBound detail` without copying the slice. The
  exact qualified toolchain's `Text` representation retained the full source
  array in the reproduction, independently of the record-update bypass.
- `docs/lua_runtime_design.md:597` requires child-originated error/cleanup text
  to be bounded untrusted evidence; the model carries these reasons into failed
  task results, provider results, session failure, and stop dispositions.

**Handoff context:**

- **Current behavior:** Even callers using the smart constructor can retain
  arbitrarily large source allocations through a 512-character detail. A caller
  using the exported field update can also retain and render arbitrarily long
  text. Count limits on stored failures therefore do not establish the promised
  bound on retained failure evidence.
- **Expected behavior:** A stored detail owns storage bounded by its documented
  character limit and does not retain a much larger source allocation. Publicly
  available operations of this private component must not permit bypassing that
  invariant; reason observation must remain available.
- **Scope and constraints:** Repair the failure value and its boundary tests in
  the private pure protocol component. Preserve the established reason codes,
  recovery-safety distinction, and character-based contract. Do not claim this
  fixes the separate OS confinement or process-memory enforcement work.
- **Verification target:** Test oversized ASCII and multibyte details, bounded
  retained storage after truncation, and a client compile check that rejects
  record-update bypass while allowing supported reason observation. If the API
  correctly removes record updates, the third reproduction below should cease
  to compile; it should become a negative compilation test rather than a runtime
  test in the repaired suite.
- **Deduplication:** The open inventory and all-state searches for `reasonDetail`,
  `failureReason`, and `"failure" "bounded" "Lua"` found no dedicated repair.
  #149 is closed origin work and #145 is the umbrella. The claimed ledger row
  had no prior report or finding links.
- **Remaining uncertainty:** None about the two observed bypasses on the
  qualified toolchain. The backing-array inspection is diagnostic test evidence,
  not a proposed production dependency on `Data.Text.Internal`.

## 3. Reproduction evidence

The following scratch program was run from the canonical detached review tree
at the verification commit with GHC 9.14.1 and the installed Hspec package
database. It imports the pinned pure model and existing pure test fixtures;
it constructs no interpreter. Save it outside the checkout as `Repro179.hs`.
The original attempt's scratch file is removed during review cleanup; this
listing preserves the complete experiment.

```haskell
{-# LANGUAGE MagicHash #-}
module Main (main) where

import qualified Data.Map.Strict as Map
import qualified Data.Text as Text
import qualified Data.Text.Internal as TextInternal
import Data.Array.Byte (ByteArray (ByteArray))
import GHC.Exts (Int (I#), sizeofByteArray#)
import Hetoimasia.Scripting.Lua.Internal.Protocol.Failure
import Hetoimasia.Scripting.Lua.Internal.Protocol.Session
import Hetoimasia.Scripting.Lua.Internal.Protocol.Task
import Test.Hspec
import Test.Lua.Protocol.Support

main :: IO ()
main = hspec $ describe "PR179 audit" $ do
  it "settles a safe failure of observing work after the session failed" $ do
    initial <- openSession
    let original = FailureRecord Nothing (failureReason AuthoritativeFault "unsafe") RecoveryUnsafe Nothing
    (failed, ()) <- ok (reportFailure original initial)
    (queued, observer) <- ok (requestAdmission (observingAdmission 1) failed)
    (active, _) <- ok (activateNext queued)
    (running, ()) <- ok (startSegment observer active)
    let handled = FailureRecord (Just observer) (failureReason ScriptFault "observer failed") RecoverySafe Nothing
        (after, result) = reportFailure handled running
    print (result, fmap taskState (Map.lookup observer (sessionTasks after)), snd (observeResult observer after))
    result `shouldBe` Right ()
    sessionFailure after `shouldBe` Just original
    snd (observeResult observer after) `shouldBe` Right (ResultFailed (TaskFailure (failedReason handled) RecoverySafe))
  it "retains only bounded storage for a truncated failure detail" $ do
    let detail = reasonDetail (failureReason ScriptFault (Text.replicate 1000000 "x"))
    print (Text.length detail, backingBytes detail)
    Text.length detail `shouldBe` reasonDetailBound
    backingBytes detail `shouldSatisfy` (<= 4 * reasonDetailBound)
  it "cannot bypass the detail bound through an exported record selector" $ do
    let forged = (failureReason ScriptFault "small") {reasonDetail = Text.replicate 1000000 "x"}
    print (Text.length (reasonDetail forged))
    Text.length (reasonDetail forged) `shouldSatisfy` (<= reasonDetailBound)

backingBytes :: Text.Text -> Int
backingBytes (TextInternal.Text (ByteArray array) _ _) = I# (sizeofByteArray# array)
```
