## 1. Toolchain activation

### PRR-1. Keep discovered compiler paths valid when creating cached links

> **Captured note:** P2 — Preserve the executable location found through a
> relative `PATH` entry when constructing the toolchain cache. PR #339 passes
> the relative discovery result directly to `symlink`, producing a broken link
> and refusing activation even though the pinned compiler is installed.

**Verification:** At `284d782d4e0ab79fb777bc644173b77ab106b725`, an isolated
scratch directory containing executable `bin/ghc` reporting `0.0.0`, all nine
`bin/<GHC tool>-9.14.1` binaries reporting `9.14.1`, and `bin/cabal` reporting
`3.18.1.0` reproduces the defect. With the process working directory set to
that scratch directory and `PATH=bin`, `_version("ghc-9.14.1", "bin")` reports
`9.14.1`; `_toolchain` nevertheless raises its missing-toolchain refusal.
The cached `ghc` link targets literal `bin/ghc-9.14.1`, and `link.exists()` is
false. Repeating with the same binaries under an absolute `PATH` and a fresh
scratch cache succeeds and reports both pins. The adapter's 17 existing checks
pass, including the shim example, which uses absolute paths only.

**Evidence:**

- `.quruntul/adapter.py:350` — `shutil.which` can return
  `bin/ghc-9.14.1` when the search path includes relative `bin`.
- `.quruntul/adapter.py:362` — the discovered string is stored verbatim as the
  symlink target; the filesystem resolves it relative to the cache's `bin`
  directory, rather than the working directory used for discovery.
- `.quruntul/adapter.py:261` — rechecking the broken shim falls through to the
  mismatched plain compiler and raises a refusal that says no pinned compiler
  is installed. `prepare` invokes activation before any suite build.
- `.quruntul/checks.py:289` — the existing real-binary shim test constructs
  absolute default and ghcup paths, leaving this valid search-path case uncovered.

A replay from a checkout of the verification pin, using only scratch files:

```bash
python3 - <<'PY'
import importlib.util, os, sys, tempfile
from pathlib import Path
from unittest.mock import patch
sys.dont_write_bytecode = True
root = Path.cwd()
spec = importlib.util.spec_from_file_location('review_adapter', root / '.quruntul/adapter.py')
m = importlib.util.module_from_spec(spec)
spec.loader.exec_module(m)
with tempfile.TemporaryDirectory() as scratch:
    scratch = Path(scratch)
    binaries = scratch / 'bin'
    binaries.mkdir()
    versions = {'ghc': '0.0.0', 'cabal': '3.18.1.0'}
    versions.update({f'{tool}-9.14.1': '9.14.1' for tool in m.GHC_TOOLS})
    for name, version in versions.items():
        p = binaries / name
        p.write_text(f'#!/bin/sh\necho {version}\n')
        p.chmod(0o755)
    before = os.getcwd()
    try:
        os.chdir(scratch)
        for search, cache in [('bin', 'relative-cache'), (str(binaries), 'absolute-cache')]:
            with patch.dict(os.environ, {
                'PATH': search, 'GHCUP_INSTALL_BASE_PREFIX': str(scratch / 'empty-home'),
                'XDG_CACHE_HOME': str(scratch / cache),
            }):
                print('installed:', m._version('ghc-9.14.1', search))
                try:
                    activated = m.Hetoimasia._toolchain(root)
                    print('activated:', m._version('ghc', activated), m._version('cabal', activated))
                except RuntimeError as e:
                    print('refused:', e)
                link = scratch / cache / 'hetoimasia/toolchain/ghc-9.14.1/bin/ghc'
                print('link:', os.readlink(link), 'exists:', link.exists())
    finally:
        os.chdir(before)
PY
```

The relative case prints installed `9.14.1`, a refusal and `exists: False`;
the absolute control prints activated `9.14.1 3.18.1.0` and `exists: True`.

**Handoff context:**

- **Current behavior:** An installed pinned compiler found through a relative
  `PATH` entry cannot be activated through the cached shim. Every suite that
  needs that activation fails before building and the diagnostic incorrectly
  identifies installation as the problem.
- **Expected behavior:** A compiler successfully discovered on the supplied
  search path remains executable through the cached links. Activation must
  either honor relative search entries or explicitly establish a supported
  path contract before caching; it must not misreport an installed pin as absent.
- **Scope and constraints:** The same helper handles both the GHC family and
  Cabal. Keep the run's private environment, ghcup's unchanged default,
  atomic cache replacement and true missing-pin refusal. Do not alter other
  repositories, actual user caches, or quruntul's measurement ledger.
- **Verification target:** Exercise mismatched plain compilers with pinned
  binaries found through relative and absolute search entries; verify usable
  cached links and the selected versions, repeated activation, and genuine
  missing-pin refusal. Use fake executable files and a temporary cache. Retain
  the existing adapter checks and their Hspec registration.
- **Deduplication:** Open tracker inventory and all-state searches for
  `quruntul toolchain` and `relative PATH` found no matching issue. The
  claim-held ledger row for #339 has no earlier report or review history.
- **Remaining uncertainty:** The experiment proves the path-resolution error,
  not its frequency on the owner's workstation. No actual compilation or
  native session was needed to establish this preparation failure.
