## 1. Validation execution ownership

### [#370] PRR-1. Watchdog overlooks descendants in separate process groups

> **Captured note:** P2 — Make the validation stage's completion and timeout cleanup cover its owned descendants that create a separate process group. The current runner observes and signals only its initial group, although its contract includes every descendant. Current native test children deliberately create another group.

**Verification:** Confirmed against `32eb02e3bcb5c7d99dc09b6edc35c90c42509c56` with a headless Python probe of the actual pinned `execute` function on macOS. A parent starts a child in another process group within the same session; a pipe handshake establishes that the child is running before the parent either exits successfully or waits for expiry. With a one-second budget, normal completion returned `passed` after 0.04 seconds while the child remained alive. Expiry returned `timeout` after 1.0 seconds, with 0.011 seconds of cleanup and `killed=false`, while its child also remained alive. The probe killed each escaped child in its `finally` block, and both PIDs were subsequently checked absent. No native session or display was acquired.

**Evidence:**

- `tools/validation/run.py:754` — `execute` promises to measure until the command and every descendant have gone. It starts a new session at line 771, saves only the leader's group identifier at line 777, and probes only that group after the leader exits at line 783.
- `tools/validation/run.py:683` — `group_alive` uses `os.killpg(group, 0)`; a live descendant in another group is invisible to this probe.
- `tools/validation/run.py:716` — `terminate_group` signals and checks only the saved group. Once that group empties, it reports cleanup complete even if another group in the launched session remains.
- `packages/gpu-vulkan/glfw/native-test/Test/GPU/Vulkan/Native/Child.hs:84` — the current child launcher uses `create_group = True` at line 91. `Private.hs:431` invokes this launcher for native private scenarios. Its independent deadline does not make the outer watchdog own that group's cleanup if the suite is interrupted or its outer budget expires.
- `docs/validation.md:1449` — the documented measurement includes every descendant and unfinished teardown; the process-group implementation supplies a narrower guarantee.
- `tools/test/Execution.hs:221` and `tools/test/Execution.hs:269` — existing leader-exit tests leave their children in the initial group. They do not cover the new-group case.

The following self-contained probe preserves the reproduction. Run it from a detached checkout of the verification commit as `python3 -I /tmp/watchdog_groups.py "$PWD" <empty-scratch-directory>`, with the script below saved outside the checkout. It writes only child PID files in the supplied scratch directory and terminates its own children:

```python
import importlib.util, json, os, pathlib, signal, sys
sys.dont_write_bytecode = True
root = pathlib.Path(sys.argv[1])
scratch = pathlib.Path(sys.argv[2])
spec = importlib.util.spec_from_file_location(
    "audited_runner", root / "tools/validation/run.py")
module = importlib.util.module_from_spec(spec)
spec.loader.exec_module(module)
child = "import os,signal,sys; os.write(int(sys.argv[1]),b'R'); signal.pause()"
parent = """import os,pathlib,signal,subprocess,sys
read,write=os.pipe()
p=subprocess.Popen([sys.executable,'-I','-c',sys.argv[1],str(write)],
    pass_fds=(write,),preexec_fn=os.setpgrp,
    stdin=subprocess.DEVNULL,stdout=subprocess.DEVNULL,stderr=subprocess.DEVNULL)
os.close(write)
assert os.read(read,1)==b'R'
pathlib.Path(sys.argv[2]).write_text(str(p.pid))
if sys.argv[3]=='expiry': signal.pause()
"""
for mode in ("completion", "expiry"):
    pidfile = scratch / (mode + ".pid")
    pid = None
    try:
        result = module.execute(
            [sys.executable, "-I", "-c", parent, child, str(pidfile), mode],
            str(root), 1, dict(os.environ))
        pid = int(pidfile.read_text())
        os.kill(pid, 0)
        print(json.dumps({
            "mode": mode, "outcome": result["outcome"],
            "duration_seconds": result["duration_seconds"],
            "expiry": result["expiry"],
            "separate_group_child_alive": True, "child_pid": pid}), flush=True)
    finally:
        if pid is None and pidfile.exists():
            pid = int(pidfile.read_text())
        if pid is not None:
            try:
                os.kill(pid, signal.SIGKILL)
            except ProcessLookupError:
                pass
```

Observed output, omitting only the child PIDs and the expiry timestamp:

```text
completion: outcome=passed, duration_seconds=0.04, expiry=null, separate_group_child_alive=true
expiry: outcome=timeout, duration_seconds=1.0, cleanup_seconds=0.011, killed=false, separate_group_child_alive=true
```

**Handoff context:**

- **Current behavior:** A successful leader can produce a passed stage while an owned child continues outside its original group. An expired stage remains unsuccessful but can return with the same child still running. This affects preparation and execution because both use `execute`.
- **Expected behavior:** Completion must account for all processes owned by the stage's promised boundary. Deadline cleanup must terminate survivors in that boundary and preserve unsuccessful expiry, while excluding unrelated processes and retaining the existing grace and evidence behavior.
- **Scope and constraints:** PR #260 introduced the shared stage watchdog and its all-descendants contract for issue #220. PR #356 later added the current Vulkan bounded-child launcher; this report audits the shared runner's compatibility with that current caller. Keep desktop opt-in, headless routing, distinct preparation budgets, cleanup timing, and receipt semantics intact. Do not fix this by broadly killing user processes or by assuming each inner launcher finishes cleanup after its parent is terminated.
- **Verification target:** Add owning workflow examples that explicitly coordinate a descendant entering another process group, then exercise both successful leader exit and outer expiry. Require the stage to stay unfinished while that child runs, require expiry cleanup to leave no owned survivor, and verify unrelated processes remain untouched. Preserve the existing same-group and stubborn-descendant tests. A native visual run is unnecessary to prove this runner boundary.
- **Deduplication:** The complete open-issue inventory and all-state searches for watchdog descendants and process groups found no issue tracking this validation-runner defect. Closed #246 concerns the removed flake process guardian's zombie/permission handling; closed #284 concerns GLFW child orphan reaping. Reports #278 and #356 concern reader threads and pipe handles abandoned by their respective child launchers, a separate correction. Claim-held #260 history is empty, so this is a new entry rather than a repeat.
- **Remaining uncertainty:** The actual runner defect is reproduced on macOS; its POSIX group-only trace also applies to Linux. The full Vulkan suite was not deliberately interrupted in this review, and no fresh native or visual result is claimed. Existing retained #260 platform receipts describe their original `a558b9ee80169f9c9d1fc4f1591755a83f054f47` / `ecf7d2a2044b0babfd316b61e95a7fbe192de6e6` executions, not this failure scenario.
