## 1. Optional probe fixture ownership

### PRR-1. [P2] Clean up the X11 fixture's inherited writer when an assertion fails

> **Captured note:** The extracted X11 example for an exited server whose startup report remains open leaves its fixture-owned FIFO reader alive when an assertion fails. Protect that reader's teardown across the example's failure paths.

**Verification:** Confirmed against the pinned SHA with a bounded, headless scratch witness using the actual current `tools/x11-test/Main.hs` fixture source and the verbatim example action. The scratch copy changed only the module/export declaration to expose its helpers. The witness substituted an immediate helper response that launches the actual `handedOffServer` stub, saves the holder PID outside the temporary scope and returns exit 2. The existing `refused` assertion raised `HUnitFailure` for expected exit 1 versus actual exit 2; after `withHelper` had unwound, `stopped holder` was false. Output was `holder_survived_failed_example=True`. The witness then ended its child and printed `witness_child_cleaned=True`. The actual fixture and witness compiled warning-clean with GHC 9.14.1, `-Wall -Werror`.

This verifies the failed-assertion ownership path. It does not show that the production X11 helper currently returns an incorrect status or diagnosis, and did not execute its startup deadlines or the optional suite.

**Evidence:**

- `tools/x11-test/Main.hs:75` — the example installs `handedOffServer`, runs `refusedStartup` and other assertions, then reaches `ended holder` only on normal completion.
- `tools/x11-test/Main.hs:345` — `handedOffServer` forks `sh -c 'read held < gate'`, records its PID and exits; the reader blocks indefinitely and is explicitly outside the helper's ownership.
- `tools/x11-test/Main.hs:519` — `refused` performs throwing status, diagnosis and command-execution assertions before the caller can reclaim its reader.
- `tools/x11-test/Main.hs:596` — `withHelper` brackets the temporary directory, but installs no process cleanup around its action; directory removal does not terminate the blocked reader.
- `tools/x11-test/Main.hs:123` — the later high-status sibling already arranges the same kind of holder cleanup with `finally`, including assertion failures.

**Handoff context:**

- **Current behavior:** A wrong helper result, a missing expected diagnostic, another failed assertion or cancellation after the stub has recorded its child can bypass the sole `ended holder` call. The optional probe can report a failure while leaving an orphaned shell blocked on a FIFO whose temporary directory has disappeared.
- **Expected behavior:** The example must retain a cleanup obligation for every descendant it creates until that descendant is stopped, on success, assertion failure and cancellation. Cleanup must preserve the original test failure and must affect only fixture-owned processes.
- **Scope and constraints:** This is local test apparatus, not a production X11-helper defect or a reason to promote optional probes into routine validation. Preserve the existing assertions, startup deadlines, consent isolation and distinction between helper-owned processes and the fixture's inherited writer. PR #240 moved this existing assertion path into `x11-helper-tests`; later #248 added exception-safe cleanup to the high-status sibling without correcting this older one.
- **Verification target:** A focused Hspec fixture check should force a failed status or diagnosis assertion after the inherited writer starts, establish that the original assertion still fails and prove the recorded writer is stopped before the fixture scope returns. Cover cancellation at the same ownership boundary. Keep successful inherited-writer coverage and empty-selector refusal; run the optional suite only through explicit local selection.
- **Deduplication:** Fresh complete open-issue inventory and all-state searches for X11 cleanup, holder and fixture descendants found no issue specifically tracking this remaining path. Closed #237 requires safe fixture descendant cleanup and its high-status sibling now has it; that issue's server-exit correction does not clean the older example. Reports #278 and #356 concern abandoned pipe-reader threads in GLFW child launchers, and #260 concerns the validation runner's process-group escape, separate owners and corrections. The claim-held #240 ledger row has no previous report or review history, so this is a new entry.
- **Remaining uncertainty:** No current production-helper failure or failing full optional-suite run is claimed. The controlled immediate response establishes what happens when this example's oracle fails. Native X11 behavior, full optional-probe execution and external lab guardian behavior were not measured.
