## 1. Reacquisition contract commentary

### [#195] PRR-1. Correct the test comment that makes rendering completion a reacquisition prerequisite

> **Captured note:** P3 — A new negative-test comment says the older submission's
> completion is what makes an enqueued image reacquirable. The accepted owner
> amendment explicitly removes that prerequisite, and the implementation and
> positive regression correctly admit the new acquisition before that completion
> is observed. Correct the comment without changing the model or assertions.

**Verification:** At the pinned commit, `Frames.hs:375–376` attributes
reacquirability to old submission completion. The positive example at line 251
acquires the same image before injecting `SubmissionCompleted`, checks that the
old submission and presentation remain outstanding, and later settles them
independently. `imageOwned` excludes `PoolEnqueued` without consulting submission
completion. The contradictory sentence could mislead a later backend solver
into reintroducing the unnecessary host-side prerequisite this repair removed.

**Evidence:**

- `packages/gpu-vulkan/model/test/Test/GPU/Model/Frames.hs:375` — the two-line
  comment says old submission completion makes an enqueued image reacquirable.
- `packages/gpu-vulkan/model/test/Test/GPU/Model/Frames.hs:251` — the explicit
  regression admits reacquisition before that observation; lines 263–266 retain
  the old obligations and lines 269–274 settle them independently.
- `packages/gpu-vulkan/model/src/Hetoimasia/GPU/Model/Internal/State.hs:1514` —
  `imageOwned` checks generation/image identity and excludes `PoolEnqueued`,
  without imposing old submission completion.
- [Issue #183's owner-approved amendment](https://github.com/coghex/hetoimasia/issues/183#issuecomment-5747028803)
  — completion in the original reproduction is not an admission prerequisite;
  the new acquisition's synchronization remains mandatory before image access.

**Handoff context:**

- **Current behavior:** Code and tests enforce the approved rule, but one
  explanatory sentence asserts the opposite condition.
- **Expected behavior:** Explain that an unpresented image still needs explicit
  settlement even after rendering completes; for an enqueued image, a distinct
  free frame and record permit a new acquisition without observing the older
  submission's completion. Preserve the requirement to obey new acquisition
  synchronization before image access.
- **Scope and constraints:** Comment-only correction to the negative example.
  No behavioral repair, new abstraction, new test or desktop session is needed.
  This does not block processing the remaining Vulkan design.
- **Verification target:** Read the corrected comment beside the existing early
  reacquisition regression and `imageOwned`; those three must state one rule.
- **Deduplication:** Open tracker inventory contains only epics. Issue #183 is
  closed by PR #187; the all-state reacquisition search found #183 and #184,
  and no issue for this residual comment correction.
- **Remaining uncertainty:** None about the comment mismatch. This review
  establishes pure-model behavior only, not native acquisition completion.
