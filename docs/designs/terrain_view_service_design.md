# Terrain views with retained chunks

Design state: `exploring` · proposal for owner approval

One window can show one terrain view. The graphics owner plans it in small steps and builds and releases its device buffers.
An unchanged region keeps its buffer. An edit rebuilds the regions whose encoded draw data changes.
If a replacement cannot fit, the current picture stays on screen. Newly exposed areas can show loading, and confirmed undiscovered terrain shows fog.
Picking uses the plan and window dimensions of the frame that was drawn.
Closing the view starts retirement. The session keeps each old buffer until the renderer proves its last use has finished.
This replaces PR #697’s background worker, capacity waits, per-object byte charging and shutdown keeper.

## Owner decisions

**D-1.** The owner approves the design before the manager files the replacement issue. **D-2.** Keep retained world-depth cutout chunks. Reuse a region across revisions exactly when its encoded instances and local material records still match. **D-3.** Each window target incarnation has one view inside one trusted graphics session. The session owns the work to its end. **D-4.** Retire superseded chunks in FIFO order through the renderer's barrier and release steps. **D-5.** Refuse work under pressure, preserve the drawn scene and represent missing coverage as loading. Only confirmed undiscovered terrain supplies fog. **D-6.** Bound the view with fixed capacities checked at construction. **D-7.** Pick the plan actually drawn. **D-8.** Use Hetoimasia's ownership, resource and rendering contracts as the engineering reference.

## Proposal · who runs each step

Install terrain as an optional participant in the graphics owner's existing session and target lifecycle. The target slot persists through closing and retirement. The session constructs its slots and registers its teardown before opening admission. Ordinary M1 publication checks the same exclusive target claim. A registered surface-free qualification target uses the same slot and renderer through its actual owner recording boundary.

| Producer → consumer | Handoff and sole writer |
| --- | --- |
| Presentation instance → target | One bounded mailbox holds an open or move settlement and the latest validated intent. The caller commits admission, supersession or close atomically. Close has a dedicated latch. A refused request changes nothing. The graphics owner alone installs the claim, owns view state and settles accepted work against current authority. |
| Terrain owner → graphics owner | A view has one runtime demand handle and at most one outstanding `requestRegionSnapshot` at a time. Its settlement makes the target runnable. Take or cancel through the runtime's request arbitration. Copy bounded immutable facts and release the borrow under protection, including when cancellation loses to settlement. The terrain owner alone changes terrain, knowledge and residency. |
| Graphics owner → renderer → target | Run a bounded pure planning/adaptation step between frames on the graphics owner. A continuation belongs to that slot and advances next turn while it has actual work. Pure facts, planning and instance assembly could run off-thread from immutable inputs. This proposal needs no additional worker, job queue or join. Chunk construction, publication, draw receipts and physical release execute on the graphics owner. |

Serve terminal events and eligible releases before a bounded round of ordinary target work. A target carries one coalesced runnable bit. Its producers set it with an accepted intent, relevant terrain/metrics change or exact outstanding operation's settlement. An idle frame or another target's release sets no bit. Runtime settlements, input changes, upload completions and target lifecycle events schedule the existing owner loop, including while a window is minimized. No owner action waits for a ticket, a frame, bank room or its own next turn. A started build returns directly into its reserved slot under the acquisition mask. The slot already owns any registered prefix on failure. Polling a refused request on every renderer turn would violate D-5.

## Proposal · one revision from facts to pixels

1. Capture arena incarnation and content/knowledge revisions, target incarnation/metrics, camera intent and effective cut, facing, projection origin, lighting/depth, and immutable atlas parents, coverage versions and region layout. Combine copies only for the same authoritative terrain and knowledge. `Facts`, `Cells`, `CellPick` and the qualified material adapter are the merged whole-cell path. Request the full projected height band and sprite envelope, including distant contributors. Give visible inputs priority over one-chunk prefetch. Retain demand for regions used by the visible plan. Unavailable terrain, delayed knowledge and unexamined columns carry explicit unresolved coverage.
2. A change to the captured inputs invalidates the candidate. Re-evaluate visibility including neighbors supplying occlusion, removals, discovery, mixed parts and changed camera coverage. Group whole quads in the same deterministic region and draw order as the material adapter. Compare full build inputs, including kind, bounds, ordered 64-byte instances, checked texture generations and local material records. Rebuild each changed region once per successful replacement. Reuse identical chunks across edits, pan, zoom and presentation changes. A push-block-only change updates the scene. Rebase, new occlusion, facing or a changed dense depth rank can change bytes outside the edited region. #696 follows TRA-9-V2 and preserves this same equality test. [Reuse decision](https://github.com/coghex/hetoimasia/issues/645#issuecomment-6908430167)
3. Changes solely to residency leave copy-derived geometry and the drawn revision intact. Sample the current generation when issuing a hit token. Arbitration checks that same generation, so a token obtained before eviction becomes stale and a new pick on the same drawing can succeed. Changed availability of previously pending inputs schedules preparation. Never update terrain/knowledge identity on old geometry.
4. Preflight the whole candidate, including the unculled frame's material-record window, chunk/quad limits, available revision slots and simultaneous old/new GPU storage. A mixed cell's complementary parts form one admission unit. Build into free slots, retain the successful prefix only while the same accepted candidate makes progress, and publish only when every listed upload is ready. In one transaction recheck authority, intent, metrics, facts, asset generations and claim, then install the forced scene and its matching pin through the host's real latest-value publication. A stale or refused candidate relinquishes only its private resources.
5. Refusal leaves the current publication and camera mapping intact. An initial or deliberately partial revision can show a neutral loading background wherever unresolved foreground could conceal a contributor. Withhold those rear pixels and picks together. Confirmed fog draws its covered pixels and hides what lies behind. No capacity waiter, retry timer or self-generated invalidation is installed. A new request or changed relevant input can make a fresh attempt. An admitted move that cannot complete within the caps settles with a typed refusal. A runtime bank, truncated camera demand, full upload queue or renderer window can refuse independently. Expose the binding reason once per transition. Cleanup proceeds even if ordinary work is refused.

## Proposal · fixed storage and retirement

| Resource | Owner, lifetime and disposal |
| --- | --- |
| Target claim, intent, move settlement, demand and pending copy | One session slot per configured target. Recheck the original instance's live lease keys, arena, target, owner admission, complete palette/atlas and D32 depth in the attach commit. Close first revokes admission, settles pending calls and withdraws only this view's runtime interests. |
| Style, GPU interests and CPU coverage | Acquire checked colour/blank and normal atlas parents through the instance's leases under `withResource`. The view holds independent exact-version interests after attach. Failed attach drops its acquired prefix. Drawn plans use the existing shared coverage planes. Renderer adoption holds every referenced parent through last use. |
| Prepared inputs, instances and plans | Bounded workspace and revision slots under the graphics owner. A revision slot holds the complete pick data through its last eligible draw and bounded pick. Reclaim on draw replacement, discard or close, including for an idle view. The host's frame-use ledger needs GPU refs after submission, so its scene must not retain obsolete pick plans. |
| Chunks, uploads, retirement and failure evidence | A fixed pool holds one slot per chunk from before build through physical disposal. Publication appends replaced slots in removal order to a bounded FIFO using those same slots. Never-published builds need only upload disposal. Submit the FIFO head through the host's dedicated release lane, retrying *cleanup* on host progress if the lane is full. A met publication barrier covers accepted scenes that could still be adopted. Every actual adoption, including a repeated adoption, keeps a hold until its last recording/batch finishes. Release-lane admission leaves the slot occupied. Recycle it only on physical release or definitive native teardown. A failed release keeps its identity and cause in place, leaves the actionable FIFO and permits independent retirement. |

**Construction and admission.** A profile fixes the session target count `W` within host/runtime limits. Each target has two revision slots (`P`), at most `R` regions, `Q` quads and `U` pending spans per revision, and `K` chunk slots across candidate, drawn, failed and retiring data. Cap a chunk's encoded cutout data at `C` bytes, a multiple of the 64-byte instance stride. A target can have one pick in progress, one regional request and one candidate. Check counts before enqueue, copying, expanding, appending or building. Use the planner's existing limits on columns, levels, proofs, demand entries, intervals and work per step. Count input runs and intervals for every admitted copy occurrence, including split snapshots. One 16×16×32 input region can have 8,192 knowledge runs and 4,096 disjoint removal intervals.

| Quantity | Bound checked at construction |
| --- | --- |
| Device vertex buffers | At most `W × K × C` bytes, including retiring and failed slots, within the session's 128 MiB allowance. A chunk with `q` cutouts uses exactly `64 × q` payload bytes. Upload staging, frame rings, depth and texture allocations retain their backend limits. |
| CPU render/staging reservation | Publish a profile table of count limits and declared bytes per counted item. For one target, let `H` be its fixed control/style/demand allowance, `F = Σ(count cap × unit allowance)` for a revision's regions, quads, spans, inputs, runs and continuation, and `D` the allowance for one full chunk description including its records. Let `S` cover one bounded owner step's transient planning, sorting, adaptation and encoding at the profile's step limits. Reserve `S + W × (H + P × F + K × D)` once in the existing 128 MiB account. The texture owner already charges shared coverage. |
| Example reservation | At two targets, 64 chunk slots each and 16 KiB/chunk, GPU payload is at most **2 MiB**. Illustrative declared CPU allowances of 16 MiB for one step, 256 KiB per target, 4 MiB per revision and 64 KiB per chunk give **40.5 MiB** at full occupancy. The implementation supplies the production counts and unit allowances. |

Use checked arithmetic for products, sums and alignment. Refuse an unsupported configuration or unavailable reservation before opening admission. Release the shared step workspace on yielding. Saved work must fit the target's candidate counts. Reopening a window cannot reuse a closing slot or reset the session allowance. The CPU sum bounds the **account reservation**. Enforce the underlying counts and record the measured GHC heap peak once at those caps, with the exercised occupancy and measurement method. Boxed objects and collector overhead are observed in that measurement.

## Proposal · picking and endings

A target can have a drawn revision and **one** successor being prepared, accepted or drawn. An accepted successor occupies the second slot until drawn or definitively discarded by the host. A superseded slot is reusable only after the host can no longer draw it and its scoped pick has returned. GPU frame holds have their own lifetime. Coalesce later changes into intent. The recorder associates the plan tag and actual frame metrics with its frame. Advance the target's pick receipt on successful presentation enqueue or, for the registered offscreen target, successful submission of that recorded batch. A skipped, failed, superseded-before-draw or merely adopted scene cannot replace it. This is the host's evidence of drawing, independent of physical scan-out and of the later completion proof needed to free a buffer.

The sole presentation VM for the target executes one bounded synchronous pick at a time against that receipt. Test access uses the same single-reader slot. Its scoped read protects the pin through forcing the result. Private qualification consumes the same pin and returns only forced scalar judgments. With a missing/zero drawable or an outside point, return `no_hit`. With no matching drawn plan, changed nonzero metrics, or potentially covering unresolved data, return `loading`. Otherwise use `pickCells` at physical pixel centres. Atlas holes continue to the rear, covered fog stops with `no_hit`, and a known covered part returns its cell, content revision and opaque token. Tokens hold small identities/validity cells only. At final removal settlement compare recipient terrain service, lease, cell, arena, content, knowledge, residency and current drawn view/target/metrics/tag. The tag binds camera, cut and asset versions. A mismatch gives `stale_view` without editing.

| End | What the owner releases | Caller result |
| --- | --- | --- |
| Explicit close | Revoke read/intent authority immediately. If the claim published, replace it with a real black empty revision and release the matching claim atomically. An unpublished claim simply returns. Retire chunks and pins in the session slot. | Idempotent logical close, `retiring` until disposal, then `done` or `already_released` per lease semantics. |
| Lease/client or arena revoked | Invalidate tokens and pending work at revocation, dispose the runtime view and hand back a still-live matching target as above. | Revoked, pending moves cancelled once. |
| Target incarnation retired | Drop only its claim and demand, retain real batch holds until completion. | Target gone. A replacement target starts with fresh identity. |
| Graphics owner ends | Its exit path stops admissions, settles queued calls, resolves started work in its own scope and enters native drain while dependencies are live. An owner fault propagates through supervision. | Stopped or failed, with the recorded cause. |
| Session ends | Quiesce targets and callers, settle/cancel copies and release borrowed data. Retire target incarnations so a minimized window cannot strand a barrier. Drain uploads, frames and releases before texture/renderer/device scopes exit. Return the fixed reservation after drain. | One terminal result per operation. Successful scope exit accounts for every slot. |
| Build/upload, handback or release fails | Discard private build prefixes through their slots. A failed handback with a still-live matching claim closes admission and escalates to session teardown with its scene protected. An unproved release retains its slot and cause until backend disposal or terminal device-loss evidence. Continue independent cleanup under the resource failure contract. | Failed work keeps its original cause and any cleanup failures. A device failure cannot report successful retirement. |

## Proposal · interface and tracker amendments

The binding needs five operations. `openView(target, arenaLease, style)` and `moveView(view, xy, optionalZ)` have bounded, cancellable request admission and exactly one settlement. Open succeeds at attach. Move succeeds at the eligible camera transition. No Z restores follow, explicit Z selects manual depth. A newer accepted move or camera configure cancels a pending jump. Lighting-only changes survive it. `configureView(view, delta)` atomically validates/coalesces pan, zoom, facing, follow/manual cut, relative slice and lighting/depth. It returns accepted or busy immediately. `pickView(view, cursor)` returns the copied result above. `closeView(view)` revokes through the nonwaiting lease path. Opaque handles, requests, compact statuses and hits are the only exported values. Keep control and inspection separate from target/renderer capabilities.
